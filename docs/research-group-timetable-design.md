# 教研组课表：最终设计决定与原型实现

> 适用范围：教研组工作区中的共享教研课表、按日教研事项、相关职责权限，以及配套的个人／学校课表复制能力。
> 本文记录已经确定的设计规则与当前仓库的实际原型实现，不包含讨论过程、修改经过或提交时间线。原型能力与尚未实现的能力分别说明，不将本机演示视为生产系统。

## 1. 核心设计决定

| 主题 | 最终决定 |
| --- | --- |
| 页面定位 | 进入具体教研组后，在工作区醒目位置显示本组共享教研课表，位于内容标签导航之前。 |
| 两种视图 | 保留简化的按节课表，提供同样风格的按日合并课表；通过按钮切换，一次只显示一种，默认按日。 |
| 共享范围 | 同一教研组使用同一份安排，不给每个成员维护独立的组课表副本。 |
| 修改权限 | 仅当前有效的本组教研组长可维护；参与教师、仅有学校查看或统筹职责的人员只读。 |
| 固定安排 | 教研课卡属于每周重复的周模板；切换周次用于查看日期投影，不创建新的周模板。 |
| 日卡事项 | 教研组长直接点击日卡添加事项；事项绑定具体日期，不自动重复到下一周。 |
| 显示精简 | 无教研安排且无日期事项的日期不生成日卡；不显示“当日无教研事项”、日卡内的添加按钮或事项负责人选择项。 |
| 双视图一致 | 拖拽或编辑按节课卡后，按日视图从同一数据源重新合并，名称、地点、日期与节次保持一致。 |
| 调整保存 | 当前组课表按每次成功操作直接保存；“完成调整”用于退出编辑并回到按日视图，不是另一次发布。 |
| 独立边界 | 维护组课表不改写成员的个人课表草稿、个人资料或课堂记录；双视图同步不等于个人课表自动联动。 |
| 复制能力 | “我的课表”与“课表中心”的编辑态支持选中课卡后连续粘贴到空格；不是要求反复打开新建表单。 |
| 主页面取舍 | “需要学校支持的事项”不作为科组主要功能区展示，不占用课表和当前工作的主要位置。 |

## 2. 页面入口、布局与视觉

### 2.1 入口

- 教师入口：`/research`（我的教研）→ 本人有效教研组 → `/research?group=<组ID>`。
- 数学组示例：`/research?group=math`。
- 获授权的学校查看／统筹人员可以进入负责对象的工作区；从课程管理进入只影响返回位置，不额外授予组内编辑权。
- 本组课表位于组工作区公共区域，切换“当前工作”“任务与协作”“活动”等标签时仍保留。
- “我的教学资料”与“校内共享资料”属于独立空间，不显示本组课表；受邀活动详情也不因此开放来源组课表。

### 2.2 页面结构

从上到下为：工作区标题与身份说明、原型／保存状态说明、本组教研课表、教研工作区内容导航、当前标签内容。

课表工具区包含：

- 上一周、日期范围、下一周、“本周”。
- “按日课表／按节课表”互斥切换按钮。
- 组长的“调整教研课表／完成调整”，或非组长的只读说明。
- “组长可维护／组员共享只读”权限标识。

### 2.3 共同视觉规则

- 两种视图都复用 `WeekGrid` 与 `ClassCard`，保持相同周表头、星期列、日期、边框和教研课卡样式；按日视图不是另起一套独立卡片列表。
- 保留周一至周日七列。没有日卡的日期仍保留星期与日期列，不填充空白占位课卡。
- 按节只读视图使用紧凑模式，主要显示有安排的日间节次；编辑态开放完整日间节次，便于新增和拖动。晚间沿用共享网格的展开／折叠规则。
- 网格最小宽度为 640px；窄屏通过横向滚动阅读，不挤压成难以辨识的卡片。
- 教研安排沿用共享课卡的浅青蓝活动色。公共视图使用 `canonical`，不套用成员个人教学任务的自定义分工名和个人配色。
- 组员不显示可操作的修改、拖拽、新增、删除入口；只读状态有文字和锁图标，不仅依靠颜色传达。

## 3. 职责来源与权限规则

### 3.1 唯一职责来源

教研访问由“职责模板＋具体教研组负责对象＋有效任期＋可用账号”决定，统一读取教职工管理中的职责。

人事部门、部门标签、任课关系、账号角色名称及链接来源，都不能单独推出教研组成员身份或课表编辑权限。处于数学部门，不等于自动拥有数学教研组访问权。

职责办理入口为：**学校管理 → 教职工管理 → 人员详情 → 安排职责**。负责对象选择具体教研组，不在教师个人教研区另设自我任命或另一套科组任命权限。

当前设计取消任职资格依赖：安排教研职责不要求先取得额外资格。无账号员工可以先登记工作职责，但没有可用账号时不能执行线上访问或操作；工作安排与账号开通是两件事。

### 3.2 课表权限矩阵

| 当前有效职责 | 查看负责组课表 | 修改固定课卡 | 点击日卡添加事项 |
| --- | --- | --- | --- |
| 教研组长 `research_lead` | 可以 | 可以 | 可以 |
| 教研参与教师 `research_participate` | 可以 | 不可以 | 不可以 |
| 学校教研查看 `research_view` | 可以，仅限获授权对象 | 不可以 | 不可以 |
| 学校教研统筹 `research_manage` | 可以，仅限获授权对象 | 不可以，仅此职责不授予组长编辑权 | 不可以 |
| 无当前有效教研职责，且无对应学校授权 | 不可以进入组工作区 | 不可以 | 不可以 |

- 同一人员在同一组可以同时拥有组长和参与教师职责；两者不是互斥模板。有效组长职责存在时可以维护课表。
- 同一组同一任期最多一位组长，可以暂缺组长；不得把同类、同负责对象的重复重叠职责当作额外权限来源。
- 已生效职责允许由有权人员结束。结束组长职责后，若仍有有效参与教师职责，则保留只读访问，不再维护课表；结束一项职责不应删除另一项合法职责。
- 未生效、已结束、已暂停、到期或负责组已停用的职责不提供当前权限。
- 权限依据当前业务日期判断，不依据课表正在浏览的周次；查看过去或未来一周不能恢复已经失效的组长权限。
- 页面是否显示按钮和保存命令是否允许执行分别检查权限。客户端命令守卫是原型行为，不等同于服务端安全授权。

## 4. 按节课表

### 4.1 固定安排的内容

每张课卡对应一条 `GroupScheduleSlot`，至少包含教研名称、星期、节次和可为空的教室。

- 星期使用周一至周日的整数 `1–7`。
- 节次使用系统 `PERIODS` 中的 ID，时间标签从系统节次配置读取，不另建教研专用时间表。
- 课卡显示教研名称和地点；未设置教室时按节课卡显示“未排教室”。
- 周视图把固定安排投影到所选周的实际日期；技术上的 `teacherId = research:<组ID>` 仅标识组安排，不代表某位真实授课教师。

### 4.2 组长调整行为

| 操作 | 原型行为 |
| --- | --- |
| 点击“调整教研课表” | 进入编辑态并切换到按节视图，开放课卡调整与空格新增。 |
| 拖拽课卡 | 修改该条安排的星期、节次；保留原 ID、名称与教室，不创建第二张副本。 |
| 点击课卡 | 打开“教研课卡信息”弹窗，修改教研名称、教室、星期或节次；选择器是拖拽以外的调整方式。 |
| 点击空格 | 创建新的组课卡，保存前可修改名称、教室和位置。 |
| 保存安排 | 校验成功后保存本组共享安排，立即更新视图。 |
| 删除课卡 | 仅删除选中的固定安排，不自动删除该日已经建立的教研事项。 |
| 点击“完成调整” | 退出编辑态，关闭课卡弹窗并回到按日视图；此前成功的修改已经保存。 |

### 4.3 保存校验

保存／删除使用 `save-group-slot`、`delete-group-slot` 命令：

- 操作者必须是当前有效的本组组长，且账号可用。
- 科组必须有效；已有课卡不能通过改字段转移到另一个组。
- 教研名称非空，长度不超过 120 字；名称和教室保存时清理首尾空白。
- 星期为有效整数，节次必须存在于系统配置。
- 同一组、同一星期、同一节次只允许一张固定课卡。落点已有本组安排时拒绝保存，提示“不会覆盖原课卡”，不自动交换、替换或并存。
- 校验或本机写入失败时返回原因，不伪装成保存成功。

这里的同格占用规则只针对本组课表，不等同于个人课表的同教师同格规则，也不代表已经完成全校教师、教室、学生群体的资源冲突检测。

## 5. 按日合并课表

### 5.1 日卡生成规则

- 每个有内容的日期生成一张日卡，汇总当日教研课次和该组安排在该日的事项。
- 只有固定安排，没有事项：仍显示日卡。
- 只有日期事项，没有固定安排：仍显示日卡。
- 两者都没有：不显示日卡，也不显示空态提示或新增占位卡。
- 同一日期内按“教研名称＋教室＋补课来源日”合并内容：相同内容的名称和地点显示一次，各节次与时间逐项列出；不同名称、地点或补课来源不错误合并。
- 节次按系统顺序排列，日卡地点留空时显示“地点待定”。
- 已有事项显示“事项名称 · 当前状态”，直接读取任务状态，不另维护日卡状态副本。

日卡内不显示“当日无教研事项”“暂无当天事项”“添加教研事项”等提示或按钮，也不为没有内容的其他日期增加课卡。

### 5.2 双视图同步

按日与按节视图共用 `ResearchState.groupSchedules` 生成的周投影。修改后不要求刷新页面、重新导入或另保存一份日课表。

- 修改名称或教室后，日卡内容和合并分组随之更新。
- 把一节课拖到另一天，仅迁移该节，不自动迁移同日其他节次。
- 一天的全部固定安排移走，且该日没有日期事项时，原日卡消失。
- 原日仍有其他固定安排或日期事项时，保留原日卡。

## 6. 点击日卡添加教研事项

### 6.1 交互与表单

仅当前有效组长可以点击日卡，打开“添加教研事项 · YYYY-MM-DD”弹窗。参与教师和学校只读查看者看到同样内容，但不能打开添加流程。

表单只包含：

- 教研事项名称：必填。
- 事项说明：可选。
- 当前安排日期及“不自动重复到下周”的说明。
- 取消、添加事项。

不出现“事项负责人”选择项；内部默认负责人为当前操作者。保存后进入本组“任务与协作”的事项／分工列表，需要调整分工时走该列表的既有授权流程。

### 6.2 数据与生命周期

日卡事项是普通教研 `Task`，不是另一套日卡专用文本记录：

| 字段 | 日卡新建时的含义／默认值 |
| --- | --- |
| `id` | 新的事项 ID |
| `group` | 当前教研组 |
| `title` | 去除首尾空白后的事项名称 |
| `scheduleDate` | 点击日卡的实际日期 |
| `owner` | 当前操作者的员工 ID |
| `requirements` | 可选事项说明 |
| `status` | 进行中 |
| `mode` | 牵头提交 |
| `parent`、`schoolTaskId` | 空，不虚构上级事项或学校任务来源 |
| `collaborators`、`submitters`、`outcomes` | 空列表 |
| `due` | 未设置截止日期；安排日期不等于截止日期 |
| `acceptance` | 默认不要求验收 |

- 事项保存后全组在原型共享数据中可见，并显示在对应日期日卡和事项列表中。
- 日期必须是真实有效的 `YYYY-MM-DD`，不能保存不存在的日期。
- 事项不随周模板重复到下一周。
- 事项绑定日期，不绑定某张固定课卡。拖动／删除固定课卡不会自动迁移／删除已经建立的事项。
- 日卡新增不要求重新选择课程、分工人员、交付资料或审批，轻量安排不替代正式活动记录。

## 7. 数据模型与同步实现

### 7.1 固定周安排

`GroupScheduleSlot` 字段定义：

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `id` | 字符串 | 固定课卡的稳定身份 |
| `group` | 字符串 | 教研组负责对象 ID |
| `weekday` | 整数 | 周一至周日，1–7 |
| `periodId` | 字符串 | 系统节次 ID |
| `title` | 字符串 | 教研名称 |
| `room` | 字符串或空值 | 教室／地点 |

当前模型不包含固定安排的生效起止日期、只改本周范围、发布版本或历史快照。因此，当前保存是修改共享周模板，不是带生效日期的新版本发布。

### 7.2 两种视图的共同投影

`GroupSchedule` 筛选当前组的固定安排，再按所选周换算实际日期并映射为 `ProjectedEntry`：

- `key` 取固定课卡 ID。
- `date` 取该周周一加上星期偏移。
- `className` 取教研名称，`kind` 为 `activity`。
- 按节视图直接交给 `WeekGrid`。
- 按日视图仍交给 `WeekGrid`，通过 `renderDay` 合并课次，并按“当前组＋实际日期”读取 `Task.scheduleDate`。

事项更新、课卡更新及视图切换均重新读取这一数据源，不能为日卡另建一份课次数组或安排副本。

### 7.3 原型存储

- 教研内容使用现有本机 `localStorage`，存储键为 `tgs:research-prototype:v2`，当前研究数据结构为 `schema: 3`。
- `useSyncExternalStore` 订阅状态；成功保存后通知同页消费者，同源标签页通过 `storage` 事件读取更新。
- 当前组职责和组目录从教职工职责存储动态读取，不由教研内容存储另行授予权限。
- “共享”在当前原型中表示同一本机、同源演示状态及其不同身份视图；不是不同设备、真实学校账号之间的在线同步。
- 保存失败有错误提示，工作区有本机保存状态与重试入口；不声称数据已经写入正式数据库。

## 8. 校历、停课与调休

两种视图都复用共享 `WeekGrid` 的校历呈现：

- 表头与周提示区显示停课、假期和调休信息。
- 固定安排在停课／调出日保留为低调的失效展示，并标注“本日不授课”，不直接删除周模板。
- 按节视图不允许拖拽到停课日，也不在该日空格开放新增。
- 来源课次可取得时，补课日展示来源课表的镜像与“补 X/X”标记；组课表没有补课日单次编辑通道，镜像不允许拖拽。
- 按日视图合并时保留补课来源，避免把普通安排和补课安排混为同一内容。

当前实现边界：

1. **跨周调休的来源周教研安排回查尚未接入。** 组课表只向网格传入所选周的投影，没有提供按来源日期重新读取组安排的回调，不能声称所有跨周补课已经完整呈现。
2. `Task.scheduleDate` 是独立的事项日期。校历不会自动把事项移至补课日，也不会自动取消、免除或重排事项。
3. 组课表没有传入 `clockDate` 以启用网格的过去日期锁定，也没有组课表历史版本保护；不能把个人课表的历史锁定能力算作组课表已经实现的能力。

## 9. 配套课卡复制：我的课表与课表中心

这项能力解决“创建多节相同内容的课卡必须反复手工新建”的问题，与教研组课表共用网格基础组件，但写入不同数据路径。

### 9.1 最终交互

- 仅在对应课表编辑态，符合可操作条件的课卡提供“复制”。
- 选择源课卡后，点击目标空格粘贴，可以连续点击其他空格，生成多节相同内容的安排。
- 网格显示正在复制的课卡名称与操作反馈，并提供“结束复制”。
- 复制不是移动；源课卡保留原位和原内容。
- 每次粘贴创建新的课卡身份，位置与实际日期取目标格，不能复用源课卡的身份或上课日期。
- 空格开放条件与新增流程一致；复制仍接受既有草稿冲突校验，不绕过落点限制。

### 9.2 保留内容与写入位置

复制保留安排名称、学科、教学分工、教室、安排类型、教学任务关联、学生群体、单元名称、备注、备注显隐和自定义显示字段；不复制源课次的历史记录身份或课堂记录。

| 页面 | 写入路径 | 生效方式 |
| --- | --- | --- |
| 我的课表 `/timetable/my` | `draftAdd`，新增到个人调整草稿 | 沿用当前草稿的单次／区间范围，应用草稿后生效 |
| 课表中心 `/timetable` | `schoolDraftAdd`，新增到选定教师的学校草稿 | 沿用学校草稿范围与发布流程，不因复制直接发布 |

**当前组课表没有接入 `onCopyCell`，不能把上述两个页面的复制能力表述为“教研组课表也已经支持复制”。**

## 10. 原型实现对应文件

## 11. 可复核的原型示例与行为标准

### 11.1 固定示例

数学组的合成周安排均为“数学教研”，地点 `D110`：

| 星期 | 节次 | 系统 ID |
| --- | --- | --- |
| 周二 | 第4节 | `m4` |
| 周二 | 第5节 | `m5` |
| 周四 | 第6节 | `a1` |
| 周四 | 第7节 | `a2` |

以 2026-10-12 所在周为例：按节视图显示四张课卡；按日视图在 10月13日、10月15日各显示一张合并卡，分别列出两节安排。其他日期没有安排或日期事项时，不生成日卡。

初始职责示例中，林老师为数学组长，周老师为数学组参与教师，许老师具有数学组学校查看职责。实际可操作性仍取决于当前账号、职责任期和组状态，不能仅凭人物名称固定授予权限。

### 11.2 行为标准

- 两个切换按钮只展示一个课表，切换后读取同一组安排。
- 非组长无法通过界面或保存命令修改、删除固定安排或新建日卡事项。
- 组长把周二两节移到周三后，周三日卡列出第4、5节；原周二无其他内容时不留空日卡。
- 原周二已经存在日期事项时，该事项仍留在周二，不能随周模板移动而悄悄改日期。
- 修改教研名称或教室后，两种视图内容一致。
- 添加日卡事项只需要名称和可选说明，保存后同时出现在当天日卡与本组事项列表，下一周不自动出现。
- 同组同格已有固定课卡时拒绝覆盖；无效星期、节次、日期、跨组修改或失效职责均拒绝保存。
- 个人／学校课卡连续复制后，源课卡不变，各副本具有新身份和目标日期，仍遵守各自草稿的应用／发布方式。

现有回归用例覆盖共享课表组长权限、两种视图共同投影、空日卡与移动后的日合并、日期事项不重复及复制内容／身份语义。这些用例不代表正式多人系统、跨周调休或生产授权已经验收完成。

## 12. 当前实现边界

- **已实现的是可操作的本机原型**：周模板增删改、拖拽、按日／按节切换、日期事项、职责联动和两个通用课表页面的复制。
- **没有正式后端与在线多人同步**：未实现数据库持久化、真实身份的服务端授权、多人并发版本校验或线上消息送达。
- **组课表不是个人课表的发布源**：当前不自动写入成员的学校发布版、个人使用版或个人草稿；也不自动修改成员课堂记录。
- **没有组课表版本与历史保护**：未提供组安排的生效区间、仅改本次、发布／采用、撤销／重做和历史快照；修改周模板会影响其日期投影。
- **没有全校资源冲突统筹**：当前只拒绝同组同星期同节次的固定课卡占用，不检查跨组或与成员课堂的教室／教师资源冲突。
- **日期事项与正式活动区分**：课表日卡显示固定安排与日期任务，不自动汇总所有 `Activity`；添加事项不会创建新的真实授课事实、出勤或课堂评价记录。
- **没有组课表复制和完整跨周调休来源回查**：不能将其他课表页面或共享组件中存在的能力，直接视为组课表已接入。

本文以上述边界作为原型能力的准确描述；不以尚未接入的生产功能替代已经确定的界面和交互决定。
