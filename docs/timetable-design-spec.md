# 课表中心 & 我的课表 — 完整设计与实施规格

> 交付对象：实施工程师（Codex）。本文件是可直接据以实现的规格说明，覆盖领域模型、命名约定、版本与差异语义、教师侧「我的课表」、教务侧「课表中心」、校历/调休、网格导入子系统，以及全部交互与视觉规则。
>
> 现有原型技术栈：Next.js App Router + React + TypeScript + Tailwind + shadcn/ui。演示态用 `sessionStorage` 持有，纯前端计算（`lib/timetable/data.ts` 为计算引擎，`lib/timetable/store.tsx` 为状态容器）。真实实施可将「计算引擎」保留、把「状态容器」替换为后端 API + 数据库，语义保持不变。

## 0. 术语与命名约定（必须严格遵守）

| 术语 | 含义 | 命名/格式 |
| --- | --- | --- |
| 教学班（TeachingClass） | 一个开课单位，绑定课程 + 学生班组 + 授课教师 | 正式名 = `<班组标识> • <课程显示名>`，例：`高一1班 • CIE 数学` |
| 教学单元组（Teaching Unit Group） | 教学班内部的分组/模块 | 简称：`P1 / S1 / M1`（网格与单元格内展示）；完整单元名：`纯数学1 / 概率与统计1 / 力学数学1`（详情/悬浮展示） |
| 安排名称（className） | 单元格主标题，等于教学班正式名 | `高一1班 • CIE 数学` |
| 地点（room） | 教室；可为空 | `D105`；空值显示「未排教室」，且不参与教室冲突判断 |
| 校版（School Release） | 教务发布的学校版课表 | 显示 `校版 vN`（N=发布序号 seq）；内部 id `SCH-2026T1-00N` |
| 个人使用版（Personal Revision） | 教师本人采用/调整后形成的使用版 | 显示 `<教师名> vN`，例：`林老师 v2` |

**单元格三段式显示（强制）**：
1. 第 1 行：**安排名称**（教学班正式名，如 `高一1班 • CIE 数学`）
2. 第 2 行：**教学单元组简称 + 完整单元名**（如 `P1 纯数学1`）
3. 第 3 行：**地点**（如 `D105`，空则 `未排教室`）

**可改名字段**：安排名称（className）与教学单元组名（group）均可在单元格详情/编辑弹窗内直接重命名（见 §4.5）。改名作为一次编辑随草稿累积，并在教师投影（`applyWeekEdits`）与教务发布（`applyTemplateEdits`）两条路径一致生效。教务「我的教学」页对教学单元组另提供「重命名」入口。

所有演示数据的教师、教室、课程均以「示例」前缀或合成命名，避免误认为真实数据。

## 1. 角色与登录

- 角色：
  - **教务管理员（admin）** — 课表中心（总览 / 发布与更新 / 校历与调休 / 导入）。
  - **教师（teacher）** — 我的课表（含个人手动调整、导入）。
- 人物（persona）由全局 `DemoProvider` 持有。教师视角默认聚焦本人课表；教务视角保留当前所选教师。
- **默认登录教师为「林老师」**（权限/内容最丰富，便于测试）。持久化 key 需带版本号，切换默认人物时递增 key，避免旧会话残留旧默认（例如 `zhou`）。

## 2. 时间与学期模型

- 演示时区 `Asia/Shanghai`，演示时钟默认 `2026-09-24T14:30`（第 4 周 周四）。真实实施用服务端时间。
- 学期 `2026学年 第一学期`，`2026-09-01` ~ `2027-01-31`。
- 数据组织：**周模板（TemplateEntry）+ 投影到实际日期（ProjectedEntry）**。周一为一周起点。
- 关键实现注意：日期加减统一用 UTC 计算（`iso.slice(0,10) + "T00:00:00Z"`），避免 `+08:00` 经 `toISOString()` 回退一天，导致「仅本次」编辑按周命中错位。

### 节次配置
- 每节 40 分钟，分三段：`morning`（第1–5节）、`afternoon`（第6–10节）、`evening`（晚1–晚4节）。
- 午间 `11:45–13:40`。
- 冲突判断按 `[start, end)` 分钟区间重叠。

## 3. 版本、继承与差异语义

### 3.1 学校发布（校版）
- 每次发布 `seq = 当前最大 + 1`，记录 `note / publishedAt / effectiveDate / changedTeachers / templates`（仅本次变化教师的完整周模板）。
- **继承**：某教师在 `seq` 未定义模板时，沿用其 `<= seq` 且变化过该教师的最近一次定义（`contentSource`）。初始基线为 `校版 v6`（SCH-006）。

### 3.2 个人使用版（教师）
- 教师每次「采用学校新版」或「应用个人调整」都会生成新的 `PerRevision`（`perSeq / effectiveFrom / sourceSch / personalCount / appliedAt`）。
- 教师某日的「当前使用课表」= 取该日适用的 `PerRevision` → 其 `sourceSch` 对应学校模板 → 叠加已应用的个人编辑（按周）。

### 3.3 差异（diff）语义（方向必须正确）
比较「学校最新适用内容（school）」与「教师当前使用内容（personal）」，逐 `key` 匹配：

| 情况 | kind | 文案 | 颜色 |
| --- | --- | --- | --- |
| 学校有、我没有 | `added` | `学校新增：<时段>`（采用后我会多这节） | 绿色 ➕「学校新增」 |
| 我有、学校没有 | `removed` | `学校未包含：<时段>`（你的个人安排保留） | 琥珀色 ➖「学校未含」 |
| 同 key 但星期/节次不同 | `moved` | `时间调整：我的 <A> → 学校 <B>` | 中性 |
| 同 key 仅教室不同 | `room` | `教室调整：我的 <A> → 学校 <B>` | 中性 |
| 完全相同 | `same` | `无变化` | 中性 |

- **文字必须自解释**，不能只靠颜色区分正负。
- 排序：变化在前（moved → room → added → removed → same）。

## 4. 我的课表（教师侧）`/timetable/my`

### 4.1 三段标签（Tabs）
顶部固定三个标签，切换时**保持页面结构不变**：
1. **我的课表** — 教师当前使用版（含个人调整）。
2. **学校课表** — 学校最新适用内容（只读参照）。
3. **差异对比** — 双栏对照 + 差异清单。

### 4.2 顶部工具区
- 周导航：上一周 / 下一周 / **「本周」**（快速回到当前周；已在当前周时禁用）。
- **「手动调整」按钮常驻**：在「学校课表」标签下**禁用（disabled）而非隐藏**，保持布局稳定。

### 4.3 版本差异提示条（关键状态机）
当存在「学校新版尚未采用」或「与学校版存在合法差异」时，页面显示提示条。规则：

1. **醒目黄色横幅**（prominent）：当教师尚未针对「当前学校发布 seq」确认差异（即 `!diffConfirmedForCurrent`）时显示。横幅内「校版 vN / 教师 vN」字样需加背景高亮。提供：
   - 「采用学校新版」入口（一键更新到学校最新）。
   - 「确认合法差异」入口（承认差异并保留双方，不改变任一侧）。
2. **确认后折叠为不显眼提示**：教师点击「确认合法差异」或「确认保留」后，黄色横幅折叠/淡化为一条低调提示，仅说明「当前版本与学校新版存在差异」，并保留**重新采用学校新版**的入口。
3. **新发布重新醒目**：`Adoption.confirmedDiffSeq` 记录「确认差异时对标的学校 seq」。当学校再次发布（`contentSource > confirmedDiffSeq`）时，`diffConfirmedForCurrent` 变为 false → **重新弹出醒目黄色横幅**（不能再停留在不显眼提示）。
4. 「确认合法差异」按钮点击后自身也应收起。

### 4.4 确认后跳转
点击「确认保留 / 应用个人调整」成功后，自动切回「我的课表」标签，不停留在对比页。

### 4.5 单元格（ClassCard）显示与状态
- 三段式内容（见 §0）。
- **来源着色**：学校内容为默认色；个人调整过的课次标注为「个人」色调。
- **锁定/只读**（右上角锁图标 + 单元格置灰、不可拖拽、不可编辑）：
  - `kind === "history"` 或 `locked`（已记录历史，aria-label「已记录，只读」）。
  - **已过去的课次**（`entry.date < today`）也需置灰 + 锁图标（aria-label「已过期，只读」），且不可拖拽/新增/编辑。
- 点击单元格打开详情/编辑弹窗，展示安排名称、完整单元名、时段、地点等；**不显示无意义的「课次身份」行**。
- **编辑弹窗可改名（强制）**：编辑弹窗提供「班级 / 课程名称」（className）与「分组 / 备注」（group / 教学单元组名）输入框，可与改星期/节次/教室在同一次提交内一并修改。改名单独发生也算一次有效编辑（进入草稿、投影到课卡）。弹窗主操作按钮文案为「保存调整」。

### 4.6 整周显示与晚间折叠
- **整周固定显示周一~周日**（7 列），即使周六/周日无课也保留列，保证布局稳定。
- 晚间段（evening）默认折叠；**当本周晚间有课时自动展开**，无课时折叠（提供手动展开/收起开关）。

### 4.7 手动调整（个人草稿会话）
教师本人编辑走「草稿会话（DraftSession）」，多次修改累积、未应用前可撤销/放弃/保存/应用：
- **scope**：`once`（仅本次，仅影响所在周）或 `range`（固定区间，自生效日起各周）。
- 操作 `EditAction`：`move`（改星期/节次/教室）、`room`（仅改教室）、`remove`（删除）、`add`（新增）；`move`/`room` 均可顺带改名（className/group）。
- **同格并存（覆盖语义，最新要求）**：当落点已有同教师的其他课次时，**两张课卡在同一单元格内并存**，而非报错或强制覆盖。两张卡都保留继续拖动的能力；若确实不需要原课卡，用户可再点其删除。**已移除强制覆盖确认弹窗**（教师侧与教务侧同步移除）。
  - 仅在**跨教师/教室/学生群体的资源冲突**（`pickOccupant` 判定为非同教师占用）时才拒绝，返回明确原因（见 §8）。
- **拖回原位自动重置（matchesBase）**：把课卡移动/改室后又拖回其**学校基线位置**（星期、节次、教室、className、group 全部一致）时，撤销本轮该单元格的编辑，恢复为「学校来源」着色，不再残留琥珀色「已修改」标记，也不产生 no-op 编辑记录。
- 守卫（guard）：历史/锁定只读；已过去日期不可改；未改变位置视为无效。
- **应用草稿** → 生成新的个人使用版，并把 `confirmedDiff` 置 true、`confirmedDiffSeq = 当前 contentSource`（应用即视为已对齐当前学校版）；应用前做快照以支持撤销（见 §4.9）。

### 4.8 保存草稿后的状态（小角标，最新要求）
- **教师保存草稿必须退出编辑态并给出反馈**：`saveDraft` 记录 `savedAt`、置 `active=false`。编辑态 `editing` **不能仅由「草稿是否存在」推导**，必须由 `active` 显式控制，否则保存后仍停留在编辑状态、无反馈。
- **不再弹出与编辑框同尺寸的大琥珀框**。保存后仅在课表**右上角显示一个小琥珀色角标**：内容为「有草稿：」标签，紧接「放弃」「编辑」「发布」三个按钮。
- 点击角标内「编辑」→ 重新展开与原来相同尺寸、相同位置的完整琥珀色编辑框（`active=true`）。

### 4.9 应用后的撤销 / 回退（Undo / Redo，最新要求）
- 教师「确认应用」后也可倒回：`applyDraft` 应用前把状态压入撤销栈；`undoApply` 恢复上一次应用前的快照，`redoApply` 正向恢复被撤销的应用。
- **UI 为图标按钮，无文字描述**：两个「撤销 / 回退」图标按钮放在 **我的课表 / 学校课表 / 差异对比 标签行**，位于「我的课表」左侧，保持界面简洁，不占据整行。
- **仅在编辑态显示**：这两个按钮**只在编辑状态（`editing`）出现**，非编辑态不显示，避免干扰阅读。

### 4.10 应用学校课表（resetToSchool，最新要求）
- 场景：教师多次本地调整后可能「回不去」原样；即使学校未发布新版，也应能一键回到**学校最新一次课表**。
- `resetToSchool`：清空教师累积的个人编辑并以学校最新内容源重新对齐；复用 §4.9 的应用快照，**可撤销**。
- **按钮文案为「应用学校课表」**（由早期「恢复学校课表」改名），**仅在「学校课表」标签页显示**，位置在「学校发布版 …」提示框的**最右侧**（`ml-auto` 右对齐）。
- 显示条件：教师存在个人调整，或学校存在更靠后的内容源版本。

## 5. 课表中心（教务侧）`/timetable`

### 5.1 总览（Overview）
- 选择教师 → 查看其当前使用课表 / 学校课表 / 状态（是否有待采用新版、是否多版本并存、是否读取失败等）。
- 支持故障演示开关（教师当前读取失败、通知失败、采用失败）以验证降级 UI。

### 5.2 学校草稿编辑与保存态（关键状态机）
教务对某教师课表编辑走「学校草稿（SchoolDraft）」会话，字段含 `active`：

- `beginSchoolDraft`：进入编辑态（`active=true`）。若已有该教师草稿（含已保存待发布），恢复为编辑态。**同一时刻仅允许一个教师的学校草稿**。
- 编辑/新增：同样做落点冲突校验，拒绝硬冲突。
- **保存草稿（saveSchoolDraft）必须有反馈并退出编辑态**：记录 `savedAt`，置 `active=false`，草稿保留待发布。
  - 修复要点：编辑态 `editing` **不能仅由「草稿是否存在」推导**，否则保存后仍停留在编辑状态、无反馈。必须由 `active` 显式控制。保存后进入「待发布（savedIdle）」态，展示一条「待发布」条带，提供：**继续编辑 / 立即发布 / 放弃草稿** 三个入口。
- `discardSchoolDraft`：放弃草稿。

### 5.3 发布（Publish）
- `publishSchoolDraft(note?)`：把草稿的模板级编辑应用到基线 → 生成新 `校版 vN`（`effectiveDate = 草稿所在周起点`），清空当前草稿与重做栈。
- 也提供样例发布按钮（`publishSample`）：改林老师两处、改陈老师一处、周老师 10 月新增（验证晚发布只影响 10 月、不吞掉 9 月更新）。

### 5.4 撤销发布 + 正向回退（Undo / Redo，关键）
线下协商后课程安排可能未落实，需支持倒回：
- **撤销最近发布（undoLastPublish）**：移除最高 seq 的发布，回滚引用它（或更晚）的教师采用修订；保留初始基线 `校版 v6` 与教师个人调整。撤销前把 `{releases, adoptions, label}` 压入**重做栈（redoStack）**。
  - 当仅剩基线（`maxSeq <= 6`）时禁用，提示「无可撤销的发布」。
- **正向回退（redoLastPublish）**：从重做栈恢复最近一次被撤销的发布快照，**避免误点撤销无法恢复**。
- **任何新的发布**（`publishSample` / `publishSchoolDraft`）都要**清空 redoStack**（新分支使旧重做失效）。
- UI：发布工具区并排「撤销最近发布 · 校版 vN」与「回退撤销 · 恢复校版 vN」两个按钮，分别在无可撤销/无可回退时禁用，并显示对应目标版本。

### 5.5 采用（教务代理/教师）
- `oneClickUpdate(teacherId)`：把教师采用到其学校最新内容，生成新个人版；无账号教师不可送达；采用失败保留原版可重试；已是最新则提示无需更新。

## 6. 校历与调休（`/timetable` 校历页 + 课表网格联动）

### 6.1 单一数据源
- 校历事项 `CALENDAR_EVENTS` 为**教务「校历与调休」页与课表网格页共享的唯一来源**，一处变更两处一致。禁止两处各自维护。
- 事项类型 `CalKind`：`holiday`（停课）、`exception`（临时变更）、`swap`（调休：某日执行另一日安排）。
- `swap` 事项字段：`date`（执行日/补课日）、`targetDate`（来源日/原安排日）、`scope`、`note`、`traceable`。

  示例：`{ kind: "swap", date: "2026-09-28"(周一,停课来源), targetDate: "2026-09-26"(周六,补课执行) }` — 语义：**9/26（周六）执行 9/28（周一）的安排；来源周一在相同范围停课**。

### 6.2 网格中的调休呈现（关键，最新要求）
调休必须**直观**，规则如下：

1. **把停课日的课表整体拷贝到补课日**：补课日（如 9/26 周六）显示的是来源日（9/28 周一）的全部课次副本。
2. **停课日不再显示课程**，但**仍显示调休提示**（该日 header 标注「停课 · 移至 9/26」之类）。
3. **补课列整体着色**：补课日**整列（表头 + 该列所有单元格）使用与调休提示条一致的强调色（teal 青色系）**，形成一个醒目色块。
   - 表头：实心 teal 背景 + 反白「补 9/28 课表」chip。
   - 列内单元格：浅 teal 底纹；补课卡片本身用 teal 色调，并带「补 9/28」小标签。
4. **补课副本为只读**（不可拖拽/编辑），避免误改。
5. **周提示条**：本周有调休时，网格顶部显示一条 teal 提示条，文案如「本周调休：9/28 停课，其课表整体移至 9/26 执行」。
6. 三处使用网格（教师 my、教务 overview、发布 publish 预览）都默认传入共享 `CALENDAR_EVENTS`，因此调休呈现三处一致。

## 7. 网格导入子系统（课表中心）`/timetable/import` 与教师侧 `/timetable/my/import`

## 8. 冲突检测（真实计算）

对一批投影课次做资源冲突检测（同日 + 时段 `[start,end)` 重叠）：
- `teacher`：同一教师重叠时间被排两节独立课次。
- `room`：同一教室（非空）重叠时间被两节占用。
- `student`：同一学生群体（`studentGroup`）重叠时间被排两节。
- 同 `key`（明确共同授课）不算冲突。
- **同教师同格并存例外（最新）**：拖动课卡落到已有同教师课次的单元格时，不判为冲突，**两卡在同格并存**（见 §4.7），二者均可继续移动/删除；不弹强制覆盖确认。
- 手动调整/发布的落点校验复用此检测；**跨教师/教室/学生群体的硬冲突一律拒绝，不自动交换或覆盖**，并返回可读原因。

## 9. 视觉与设计规范

- 颜色总数 3–5 种：中性底 + 主品牌色 + 强调色。**调休强调色统一为 teal 青色系**（提示条、补课列、补课卡片一致）。
- 差异语义色：`added` 绿色、`removed` 琥珀色，且必须配自解释文字。
- 只读/锁定/过期：单元格置灰 + 右上角锁图标 + 合适 aria-label。
- 版本字样（`校版 vN` / `教师 vN`）在提示条内加背景高亮。
- **草稿态角标**：保存草稿后不用整块大横幅，改用右上角小琥珀色角标（「有草稿：」+ 放弃/编辑/发布），减少对阅读区的干扰（见 §4.8）。
- **实体新建统一用右侧抽屉（Sheet）**：行政班、教学班、教职工、学生四类新建流程一律采用同一右侧抽屉样式（不用居中 Modal），保证跨模块一致（教职工新建已由 Modal 迁移为 Sheet）。
- 布局优先 flexbox，复杂二维用 grid；移动优先、响应式。
- 图标用项目现有图标库（如 lucide：`Lock`、`Undo2`、`Redo2` 等），尺寸统一 16/20/24。
- 无障碍：语义化标签、正确 ARIA、锁定/停课/补课状态可被读屏识别。

## 12. 变更记录（本次修订，相对上一版）

本次修订将上一版之后落地的所有改动并入规格，主要涉及教师侧交互与全局新建样式：

1. **教学单元组/教学班改名**（§0、§4.5）：单元格编辑弹窗新增「班级/课程名称」「分组/备注」输入；改名随草稿累积，`applyWeekEdits` 与 `applyTemplateEdits` 两路径一致生效；教务「我的教学」页提供单元组「重命名」入口。
2. **同格并存取代强制覆盖**（§4.7、§8）：拖到已有同教师课次的单元格 → 两卡并存、均可继续移动/删除；移除强制覆盖确认弹窗（教师侧 + 教务侧）。
3. **拖回原位自动重置**（§4.7）：`matchesBase` 比对星期/节次/教室/className/group，全部与学校基线一致时撤销本轮编辑，去除琥珀色标记，不产生 no-op 记录。
4. **保存草稿改为右上角小角标**（§4.8、§9）：`saveDraft` 置 `active=false` 并退出编辑态；不再弹同尺寸大框，改为右上角「有草稿：」+ 放弃/编辑/发布小角标；「编辑」重开完整编辑框。
5. **应用后可撤销/回退**（§4.9）：`applyDraft` 应用前快照，新增 `undoApply` / `redoApply`；图标按钮置于标签行「我的课表」左侧，**仅在编辑态显示**。
6. **应用学校课表**（§4.10）：`resetToSchool` 允许在学校未发布新版时也回到学校最新课表并可撤销；按钮由「恢复学校课表」改名为「应用学校课表」，仅在「学校课表」标签显示，位于「学校发布版…」框最右侧。
7. **实体新建统一右侧抽屉**（§9）：行政班/教学班/教职工/学生四类新建统一为 Sheet 样式；教职工新建由 Modal 迁移为 Sheet；学生新增（`新增学生`）经右侧抽屉写入。
