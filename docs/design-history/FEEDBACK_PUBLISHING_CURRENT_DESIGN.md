> 更新：2026-10-05。整理范围：发布工作台 r1、班级与个人精细定制 r2，以及后续多轮日期、作业表头、元信息、条件格式、列宽、出勤资格、教务/主班联动、校历周期和发布免除优化。
> 第 12–16 节补记此前总览之后的设计与实现，并明确覆盖前文旧口径；原始 r1/r2 验收文档保留当时结论，不倒写。
> 状态：已实现交互原型，待 Owner 核验；不是生产系统、真实发送或全项验收通过声明。
> 本文以当前源码为准。历史设计与验收记录保留原貌；与本文冲突的旧设计仅作为演进记录。

## 1. 目标与边界

发布系统将“我的教学”的整周课堂、作业、教学介绍、学情介绍等源记录，投影为可预览、可冻结版本、可导出的班级和个人反馈。发布不是再次录入评价，也不是修改源记录的入口。

核心原则：

- 同源数据：周反馈、作业评价和发布使用已有业务记录与有效资格投影，不另建一份评价事实。
- 整周范围：从日卡进入也不缩小为某一天；按教学分工和当前教学周组织。
- 先核对再发布：实时预览辅助编辑，最终实际预览用于确认；两者均不等于发布。
- 快照与交付分离：发布保存内容和模板快照，出图、下载、模拟发送、已读是不同状态。
- 历史不变：后续源记录、模板和主题变化不回写旧报告。
- 紧凑优先：减少重复说明、重复配置与无意义版本，把可视空间留给学生信息和报告预览。

当前运行在模拟业务存储与合成身份上。家长收件箱、监护关系、发送、阅读链接均为演示；无真实家长认证、服务器授权、跨设备报告共享和真实通知，不得将其当作可处理真实学生信息的生产授权方案。

## 2. 入口与页面职责

“我的教学”任务工作区 → “发布与历史”，包含三个子页；查询参数 `publishing` 取 `prepare`、`templates`、`history`。

| 页面 | 职责 | 不承担的职责 |
| --- | --- | --- |
| 发布准备 | 范围、模板、交付选项、本次样式、受众、核对、实时预览及确认发布 | 直接更改课堂或作业源评价 |
| 模板中心 | 可复用结构样式、配色主题、默认样式、实际内容预览 | 保存本周学生、正文或日期为模板数据 |
| 发布记录 | 查看冻结版本、PNG/ZIP、模拟补发、阅读入口、撤回访问、发起修订 | 将当前未发布修改混入旧版重导出 |

顶部课堂评价和新作业默认方案入口只在整周反馈、作业评价页显示；发布与历史、教学计划页不显示。

## 3. 发布准备布局与交互

桌面端为左右两栏，比例约 0.9:1.1：左侧配置独立滚动，右侧实时预览。窄屏回落为纵向布局，不承诺手机端编辑和预览同时占据完整视口。

左侧顺序：

1. **本周发布**：紧凑显示班级反馈数量、额外个人反馈选择；移除当前班级课程的重复展示和范围长说明。有可组合的其他同班、同课程、同教师分工时仍显示选择项。
2. **模板与交付**：班级/个人模板选择、模板中心入口、模拟家长账户发送、本浏览器阅读链接。交付限制放入折叠说明。
3. **修改报告样式（仅本次）**：替代原“本次报告调整 · 不改变系统模板”；修改本次覆盖，不修改系统模板，可另存为我的模板。
4. **个人受众及公开内容**：仅开启额外个人反馈时显示；搜索、分页不改变已选受众，支持选择全部适用学生和清空。
5. **核对与发布**：版本差异、阶段反馈、待核对作业暂不纳入、错误及源记录处理入口，最后进入发布前实际预览。

已移除发布准备中的“作业检查日期 · 独立于授课日”控件。底层 `Preparation.homeworkDates` 及日期投影兼容能力仍存在，不能把 UI 移除理解成底层字段删除。

准备以教师、任务、周期组成的键保存；保存失败保留输入并提供重试。当前准备带 `classicVersion: 23`，不匹配的旧准备按当前默认配置初始化。

## 4. 发布范围与报告类型

- 默认开启一份班级报告，额外个人报告默认关闭。
- 可组合范围限定于本人有权的同班、同课程教学分工；名单去重，不纳入其他教师的任务。
- 个人报告只生成给显式选中的适用学生；班级报告受众是组合范围名单。
- 新生成报告只包含班级家长版及选中学生的个人版，班级报告排在前面。
- **不再生成重复的“校内核对”班级版**：该版原本附加明细，但后续表格化投影移除了这些额外块，内容已重复，因此删除其生成步骤。
- 旧快照仍可包含 `audience: internal`；模型、权限判断、历史标签和文件名仍保留兼容，不做历史数据删除。
- 当前部分预览提示仍保留“校内版不进入家长渠道”等旧文案，属于待清理文案，不意味着新报告仍生成两个班级版本。

## 5. 内容来源与投影

`prepareReports` 负责组合名单、作业、共同正文、学生记录和报告表格。

### 5.1 共同与个人内容

- 教学介绍、学情介绍读取同一周总结；多个教学分工组合时可标明分工来源。
- 班级报告包含共同介绍、班级矩阵、适用亮点及后续安排，不直接套用个人评语。
- 个人报告关联指定学生的课堂、作业和亮点；个人评语需要在本次公开内容中选入。
- 选入观察需满足源记录存在、所属教学分工及作者匹配、课次匹配和学生适用资格等条件；不是把所有内部观察直接公开。
- 空内容不应为凑版面保留无意义占位；报告也不能仅有标题或评价说明而发布。
- 共同正文含已知学生姓名时给出提醒；该检测不是完整敏感信息识别或隐私审核。

### 5.2 课堂与作业语义

- 未来课次不算已完成；出勤、评价资格矛盾必须返回源记录处理。
- 未记录、不适用、明确不评价和有效评价是不同状态，不混同为零分或差评。
- 作业提交状态与质量等级分离；适用要求、选做参与、延期和核对状态保留业务含义。
- 到期待核对作业需处理，或显式选择本次暂不纳入；暂不纳入不会清除源待办。
- 已布置但尚未到本期完成时点的适用作业可作为后续安排，不伪装成已完成结果。
- 表格和经典矩阵由专门数据模块生成，正文中的重复课堂/作业块会过滤，避免重复展示。
- 课表读取失败会阻断发布，不能把失败当作无课；校历排除日按来源说明，不计缺勤或课堂评价。

## 6. 模板中心与本次样式

### 6.1 样式、主题、内容分离

- **样式**决定结构与排布；切换样式不应重置已选配色。
- **主题**决定配色；切换主题不应更换布局。
- **本次样式**保存在发布准备的 `classStyle` / `personalStyle`，只作用于当前准备。
- 模板保存的是结构、显示选项及相关配置，不保存当前学生、日期或周正文。
- 系统模板不可直接改写，通过“复制为我的样式/主题”创建个人配置。

当前系统样式为六套：

| ID | 类型 | 样式 |
| --- | --- | --- |
| C01 | 班级 | 经典边栏型：矩阵在左、说明在右 |
| C02 | 班级 | 上下分区型：矩阵在上、说明在下 |
| C03 | 班级 | 紧凑纯矩阵型：高密度矩阵 |
| P01 | 个人 | 标准跟进单 |
| P02 | 个人 | 表格详报 |
| P03 | 个人 | 家长沟通版 |

旧 r1 的“八套模板”不再是当前数量。旧布局类型和兼容升级函数仍在代码中保留。

编辑项涵盖说明区位置、表头结构、作业附表、亮点呈现、字号密度、边框、空值表达、等级说明及配色等；具体可选值以 `report-options.ts` 与编辑�����为准。

模板中心同样采用桌面左右布局：左侧两列样式/主题卡片及编辑器可独立滚动，右侧保持实际报告预览。编辑尚未保存时不允许直接应用，需先保存或取消。

### 6.2 默认与归档

- 默认样式按教师、报告类型分别保存，用于新的发布准备；已有准备不随默认值自动变化。
- “归档”仅针对个人自定义样式，将 `archived` 标为 true，从活动列表及可选模板中隐藏；不是报告归档，也不是彻底删除。
- 已发布快照不受影响。当前没有恢复入口，也没有归档时自动清理所有默认引用的独立流程；选择模板时有系统模板回退。
- “停用样式”曾被建议为更直观名称，但当前按钮仍为“归档”，不能将建议写成已实现。

### 6.3 颜色校验修正

- 颜色接受 `#RGB` 和 `#RRGGBB`，格式与结构校验仍是硬性要求。
- 对比度不足仅显示可读性建议，不阻止合法颜色的预览、保存和应用。
- 建议检查表头文字/背景、隔行背景/正文、报告背景/正文以及主色/背景。
- 模板中心预览有 250ms 合并更新；暂时输入非法颜色或配置时保留上一份有效配色，不因输入中间态破坏预览。
- 截图中的 `#9243a8` 与 `#234d73` 属于合法颜色组合，即使对比度低也不再被当作格式错误。

## 7. 预览、确认及版本创建

### 7.1 两种预览

- **实时预览**：随当前配置与投影更新，供边编辑边查看；不产生正式版本。
- **发布前实际预览**：复制当前报告、源版本标记和配置签名，用户核对后确认发布。
- 切换预览对象、搜索预览报告不改变实际发送受众。
- `ReportView` 提供查看比例、输出页选择和可访问文字/表格；预览与导出复用报告渲染路径。
- 可导出带“未发布预览稿”标记的 PNG，不产生发布或送达记录。

### 7.2 发布前约束

当前工作台检查：课表可读、至少一种报告类型、任务权限有效、个人名单有效、源记录保存完成、模板有效、考勤/资格一致、有有效可见内容，以及与上一版存在内容或呈现变化。

未完成课堂记录需处理或显式发布阶段反馈；到期待核对作业需处理或明确暂不纳入。预览后源数据或配置变化会标为过期，要求刷新并重新核对。

发布函数要求预览存在、未过期、已确认且无阻断错误；使用提交锁和幂等键。正式发布调用存储层发布能力，保存报告、模板、受众、源标记及版本差异，随后再处理可选模拟交付。

同范围同周期与上一版完全一致时不新建重复版本，应到发布记录重导出或补发。

## 8. 历史、修订、导出与交付

### 8.1 发布记录与修订

历史列表按当前任务、周期、可访问任务及作者筛选，倒序分页，每页 10 个版本。旧版快照仍有兼容查看入口。

“基于此版本修订”返回当前准备并设置修订基线、范围和个人名单；**不是完整恢复当时所有准备设置**。新报告仍由当前源记录和当前准备构建；差异可包含明细、模板、受众、正文模块以及新增/移除报告。旧版不覆盖。

### 8.2 出图与导出

- 单份报告生成/重试 PNG；长报告可有多张输出。
- 当前版本的全部个人报告可导出 ZIP，包含失败清单；下载不代表送达。
- 文件名包含报告类型、周次、名称、报告 key、版本与分段，并替换非法文件名字符。
- 生成状态按发布版本与报告 key 记录 `generating / ready / failed`、尝试次数、页数和错误；出图失败不应新发一个内容版本。
- 报告渲染由经典、表格及通用导出模块分工；中文出图字体与许可证沿用仓库资源。

### 8.3 合成交付与受限阅读

- 只向具备有效、已核验监护关系的合成账户演示投送；没有核验账户的学生仍可导出图片，不自动创建真实账户。
- 补发针对选中的冻结版本，成功接收方不重复发送；可注入一个接收方失败并重试。
- 阅读链接默认 7 天，可停用；链接不代替身份与监护关系检查。
- `canRead` 拒绝无关、失效、未核验监护关系及校内报告；个人报告还需匹配该学生。
- 无 token 的账户读取需存在成功交付记录；有 token 时需匹配报告且未停用、未过期。
- “记录人工发送”仅记录人工操作，不证明系统送达或已读。
- 撤回线上访问会阻止后续读取，但不能收回已经下载的静态图片。
- 以上均是本浏览器模拟存储下的行为，不能视为服务器级安全保证。

## 10. 设计演进与未完成项

| 早期设计/问题 | 当前结论 |
| --- | --- |
| 大块发布范围、重复班级和长说明 | 紧凑“本周发布”信息框 |
| 调整、日期、交付纵向堆叠，预览被挤出屏幕 | 交付紧随范围，本次样式随后；桌面编辑与预览并排 |

| 班级家长、校内核对两份内容重复 | 新报告只生成班级家长版，旧记录保留 |

- 完整连续验收仍需覆盖过期预览、保存失败、重复提交、修订重导出、失败补发、链接过期/停用/撤回、大班与长内容出图等。

## 14. 校历、假期与调休周期规则

发布任务的候选范围仍来自在学期和周内有效的任课任务，但是否承担发布义务必须继续读取校历投影，不能仅凭任课有效期生成欠交任务。

1. 使用与“我的课表”相同的 `teacherWeekEntries` + `effectiveWithCalendar`：学校已采用版本、已应用个人调整、停课、假期、调休及补课；未应用草稿不算正式课次。
2. `scheduleReadOfWeek(week, teacherId)` 支持指定任课教师；教务和主班逐任务读取该教师的安排，不再误用当前登录教师的课表。桥接缓存按教师及周组合隔离。
3. 调课/补课以**实际授课日期所在周**承担反馈义务，跨周移走的课次不在原周重复计算，移入的周末课次纳入新周；不改变稳定周期 ID，不把两个自然周默默合并。
4. 周内存在有效课次，或按既有 `assignmentWeek` 规则归于本周的非撤回作业，才为“应发布”。部分假期不免除仍有课/作业的任务；整周无课且无本周作业为“本周无需发布”，不计逾期。
5. 默认截止为实际授课所属���周日 23:59（北京时间），周末检查从周六开始。后续已增加任务×周期的自定义截止配置（见第 17–18 节），但未实施自定义发布周期。
6. 课表未采用、未载入或读取失败为“课表待确认”，不能等同于放假、无需发布、待发布或全部完成。存在未确认且未发布任务时阻止登记完整周检查，提示先恢复来源或明确免除。
7. 已发布内容、历史检查快照不会随校历修改而改写；当前清单可以随已应用校历重新计算。若业务要固定历史发布义务，生产阶段需增加带版本的发布任务/校历依据快照，不能依赖当前纯派生模型。
8. 首次按时发布后修订不算补发；首次有效发布超过周期截止记为补发。撤回规则沿用原逻辑。

这套规则依赖学校实际录入的校历，不会自动假设某个法定节假日一定放假；校历未录入不能凭日期猜测停课。

## 15. 教务免除、恢复与教师联动

**作用范围：一个任课任务 × 一个稳定反馈周期**。教务可免除任意候选任务（包括已发布、无需发布或待确认任务），不自动批量免除同教师、同班或其他周期。

- 操作需当前演示教务角色；打开确认表单，展示任务与周次，必填原因（最多 1000 字），确认后通过现有存储命令保存。失败保留表单输入。
- `MtBiz.publicationWaivers` 追加记录：`taskId / periodId / waived / reason / actor / at`。最后一条决定当前状态；恢复也追加记录，不删除既往免除。旧存储缺少字段按空列表兼容。
- 教务清单可筛选已免除，展开免除/恢复操作记录查看原因、人员与时间。
- 教师任务列表显示“教务已免除发布”，不再属于待发布筛选；仍可进入课堂登记、维护作业和源记录。
- 发布工作区展示免除原因与操作人；免除任务不能新建发布版本，组合发布不能绕过。工作区校验和 `mt.publish` 保存层都重新校验；如需发布，应先请教务恢复，或从组合范围取消已免除的其他分工。
- 已发布报告、课堂状态、作业记录、周总结与历史检查不删除。免除后旧报告仍可读，不等同于撤回。
- 恢复按原周期截止时间重新判断，不自动延长截止；可能立即进入逾期待发布。恢复前应让管理员知晓该影响。
- 检查快照区分待发布、逾期、免除、无需发布、来源未知。只有“待发布/逾期待发布且无报告”算未完成；过去确曾未完成的检查记录不会因后续补发或免除消失。
- 学期“检查时未完成”是历史事实，不是当前欠交，更不是 KPI。当前免除数量和待发布数量独立展示。

安全与存储边界：沿用此前用户明确选择的浏览器交互原型范围，本轮不擅自替换生产数据库。页面角色检查与本地命令校验不是服务端授权；生产化需要服务端角色/主班范围授权、不可篡改审计、持久化事务和并发检查。

## 17. 追加：整周假期自动免发、集中规则与教师档案

### 整周假期

- 校历七个自然日全部被假期事件覆盖（可由多条事件拼接），直接确认整周假期；显式假期覆盖补课目标日，避免残留调休记录阻止免发；判断在个人课表采用/读取检查之前完成，因此未采用课表的教师也不会被误标“课表待确认”。

- 修复验证：类型检查、发布规则回归和 81 项报告回归通过。浏览器用日期事件注入配置截图中的假期（原生日期控件自动填写不兼容），实际点击保存并导航后，教师四项、教务五项均显示假期无需发布，教务无个人课表错误提示、无恢复按钮。此验证不代表原生日期输入自动化通过。

### 集中管理 `/management/publication-settings`

- 所有发布版本按发布时间排序、20 条分页，包含修订和撤回审计元信息；非撤回版本可打开冻结报告，撤回版本不可阅读内容。
- 跨周任务进度可查看当前状态与生效截止；检查明细保留检查当时事实。已发布任务、版本数和免发数量不是同一口径，不以版本数代替完成数。
- 数据范围是当前单学期模型内截至演示时点的所有记录，不声称包含尚未接入的往届学期档案。

## 18. 多轮收敛后的交互与联动约定（2026-10-05）

本节与第 17 节共同作为当前规则；第 13–16 节保留演进背景，涉及旧入口、假期前置条件及截止配置时，以这里的约定为准。本次只补充设计记录，不改业务代码。

### 18.1 教师、教务与主班共用一套发布事实

- 发布义务按“任课任务 × 稳定反馈周期”判定，教师任务、发布工作区、教务清单、主班任务与跨周档案不得各自猜测状态。按对应任课教师读取有效安排，而不是按当前查看人的个人课表判断。
- 教师发布后，管理侧联动显示最新有效报告与完成状态；管理侧只读查看冻结报告，不代教师编辑、发布，不用当前草稿重建历史版本。主班只读取其学生范围内的个人报告与摘要。
- 区分当前义务、发布版本和历史检查三类事实：免除不等于撤回，修订不等于多完成一个任务，后续补发、改期或免除不抹去检查当时未完成的记录。
- 候选任务在假期仍可保留，用于查看免发依据、历史报告和检查记录；不能仅因列表中仍有任务就判为欠交。当前无需发布且没有报告时，发布时间显示“—”，不显示“尚未发布”。

### 18.2 自动免发的最终优先级与冲突案例

- 整周七个自然日被学校实际录入的假期覆盖时，先确认自动免发，再考虑个人课表采用/读取状态；因此不能在这一场景显示“尚未采用学校课表，暂无有效个人安排��或“课表待确认”。
- 明确停课覆盖补课目标日。复现案例：录入 2026-10-01 至 2026-10-11 假期，同时保留 10-08 调至 10-11 的补课；10-11 仍停课，第 6 周应自动免发。若假期缩短至 10-10，10-11 补课仍正常生效，不可把所有调休一律取消。
- 完整假期不因假期作业恢复发布义务，不写人工免除记录；课堂、作业和历史报告保留。校历调整后，当前状态重新计算，发布快照和检查快照不变。
- 非完整假期按实际课次与本周作业继续判定；真正无法确认课表来源的任务独立显示待确认，既不当作欠交，也不当作已完成或无需发布。
- 教师侧显示假期提示和免发状态；教务侧将“无需发布”“教务已免除”“课表待确认”分开筛选。自动免发不仅是标签，发布工作区及保存层都应阻止误发。

### 18.3 免除与恢复的操作层级

- 教务任务行仅在尚未免除且应发布或来源待确认时提供“免除此周任务”；确认需原因。已经无需发布的行不重复提供免除操作，已免除的行不替换为恢复按钮。
- 恢复是低频管理行为：教师列表、普通任务行不放恢复按钮或显眼恢复链接，统一前往 `/management/publication-settings` 的集中管理操作。集中页支持按教师、任课分工与周次范围预览后批量确认。
- 恢复只取消人工免除，不覆盖校历自动免发；恢复后按当时生效截止重新判定，可能立即逾期，不自动延期。需要延期时单独调整截止。
- 免除、恢复、截止和发布要求各自留痕。教学管理页“免除 / 恢复操作记录”位于页面最下方，在任务清单、周末检查登记和检查历史之后，默认折叠，按所选周展示；学期视图下也仍对应当前所选周，不冒充全学期审计。

### 18.6 作业管理“结束检查”的语义澄清（2026-10-05）

上次更新后，会话补充解释了作业管理的“结束检查”按钮。本节记录现有实现的含义，不代表新增功能或调整业务规则；主班紧凑布局及隐藏免除任务的设计已记录在第 18.5 节，不重复记为本轮实现。

- **主要作用**：将作业生命周期从 `ACTIVE`（进行中）改为 `CLOSED`（已结束检查），暂停该作业学生结果的登记和修改。可理解为“这份作业暂时收工”，不是“所有学生都已完成”。
- **保留事实**：保留原有成绩、未交状态、其他学生结果与操作历史；不删除作业，不自动将未交改为已交，不自动完成待评价、未登记或安排待核对项目。生命周期变更追加操作日志。
- **未结项提醒**：按钮根据 `ungraded + dueUnrecorded + suspected + review + notDue` 判断是否还有未结项；非零时先确认，并明确提示“结束检查不等于核对完成，这些项会保持原状”。取消确认不执行关闭。
- **恢复处理**：关闭后展示“恢复处理（补交）”，将同一份作业恢复为 `ACTIVE`，在原作业内继续处理，而不是创建新作业。恢复不解除学生结果的截止后锁定规则；能否写入仍由 `writeBlock` 校验。
- **与撤回区分**：`CLOSED` 不是 `WITHDRAWN`。已撤回作业不能通过恢复处理回到进行中，需要复制为新作业；不能把“结束检查”解释成撤回或删除。
- **与反馈发布区分**：结束检查不等于发布周反馈，也不等于免除反馈发布义务；该操作仅更新作业生命周期并记录日志，不触发发布或免除操作。
- **实现定位**：`components/mt/homework.tsx` 负责按钮、未结项确认及恢复入口；`lib/mt/store.tsx` 的 `setLifecycle` 保存状态和日志；`lib/mt/hw.ts` 的 `writeBlock` 阻止关闭作业的结果写入，并在恢复后继续检查对象范围及截止后锁定。
- **验证边界**：本轮核对上述现行代码并整理文档，未修改业务代码，未重新执行作业交互或发布回归测试；此前会话中的解释不作为新增测试通过证据。
