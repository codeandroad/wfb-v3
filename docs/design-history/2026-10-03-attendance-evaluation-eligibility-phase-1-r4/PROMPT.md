## 0. 目标、范围与替代关系

在当前工程直接修复以下核心问题：

**学生没有参加本教学任务相应课堂时，不得给出该范围的课堂评价，不得新增或采用该范围的课堂亮点。请假、缺勤、在他班均不能被当成在本课堂出席。**

同时修正当前截图中仍存在的内部 ID、重复说明、乱码，以及整周预览的必要范围表达。

保留当前已经正确的：
- “我的教学”同页教学任务／课次安排／按日记录。
- 日卡原位记录弹窗、同源周矩阵和学生反馈抽屉。
- 单课次观察仅作参考，不恢复逐课次等级。
- 系统／个人评价方案、课堂与作业分别默认、方案修订及历史保护。
- 常用原因／亮点和自由填写。
- 日卡轻量布置作业、同一个整周预览、阶段发布与补发布。
- 个人课表、真实拖拽、采用、差异和跨周放弃等已有能力。

本版明确替代 r3 中不够精确的“全天未参与时核对适用性、保留原等级”解释：
**保留的是变更历史与可追溯原文，不是将无依据等级继续作为当前有效结果。不得以等待核对为由，继续允许填写或发布未出席范围的评价、亮点。**

不重跑旧提示词，不回滚当前工程，不另外创建反馈编辑器。
不开始第二阶段作业模块全面重构，不改人员编号、IAM、GPA或真实数据库。
沿用当前原型栈，必要时修改共享业务逻辑和模拟存储；不要为了本轮新建真实后端。

下面规定元素、行为、导航和数据约束，布局与视觉由 v0 决定。
不照搬问题截图中的布局、内部代码、固定人数或演示日期。
先核对实际实现、简短说明相关修改位置，然后直接实施。

## 2. 统一术语与评价资格

### 2.1 使用实际状态，不使用显示字符串猜测

“缺席”按现有“缺勤”业务状态处理；“在他班上课”对应现有“在他班”。
复用项目真实枚举和关系，不新增同义出勤状态。
中文、英文、个人标签、原因短语都不能成为资格判断键。
不开放教师自行关闭这条规则；自定义评价方案不能改变是否有资格被评价。

判断至少带入：
当前学校、真实任教责任/教学任务、学生、实际日期、真实课次及学生适用范围、已确认出勤事实、当前记录版本。
不要依据某天是否有课程、默认“正常”候选或只要不等于“请假”就视为到课。

### 2.2 状态规则

| 情况 | 课堂评价与课堂亮点 |
|---|---|
| 相应已发生课次确认为请假、缺勤、在他班，且没有本任务的实际参加范围 | 禁止写入该范围评价和亮点 |
| 正常出勤，事实已确认 | 可依现行方案评价，亮点仍须教师明确添加 |
| 迟到或早退，但确实参加了本课堂的一部分 | 可以评价实际参加部分；不因迟到/早退自动降级 |
| 出勤尚未记录、相互冲突或无法核实，且没有其他明确参加范围 | 不假定出勤；先核对出勤，再允许相应评价和亮点 |
| 未来课次、取消课次或学生不适用的课次 | 不生成课堂评价与亮点，不伪造记录 |
| 同日多课次，有明确出席，也有请假/缺勤/在他班 | 缺席课次不能作为评价或亮点依据；日综合评价仅基于实际参加的部分 |

既有“未评价/明确留空”规则继续保留，不因可评价就强制给等级。
出勤原因仍选填。已经核实未出席，即使原因未知，也必须禁止该范围评价。
教师选择常见原因，不自动改变出勤、不创建请假批准。

“在他班”在当前教学任务中就是未出席。
不复制其他教学任务的评价或亮点，不自动给当前教师扩权。
该生在另一真实课堂的记录，只能由有权主体按那一任务的真实参与情况处理。

### 2.3 合并日卡的范围不能误伤

保留“一名学生、同一任务、同一实际日期，一份综合评价”。

例1：当天只有第3节，记录为请假。
结果：本日评价不适用，不能填写本日课堂亮点。

例2：当天第3、5节均未出席，不论分别是请假还是在他班。
结果：本日没有可评价参与，禁止本日等级与课堂亮点。

例3：第3节正常，第5节请假。
结果：第5节不可产生课堂评价依据或亮点。
本日综合评价可以基于第3节，不代表给缺席的第5节评分。
某条亮点若明确关联第5节，即使第3节到课也不能保存该条。

不能只要一天中出现一次“请假”，就删除其他真正参加课次的评价依据、
其他日期亮点、整个周期评语或其他任务记录。

当天已发生课次均未出席、但尚有未来适用课次时：
当前无可评价参与，不提前评分或添加课堂亮点；
不因此宣告整个日卡永远“无需评价”或提前完成未来覆盖。
后续真正出席后才重新获得相应资格，沿用既有阶段记录规则。

## 3. 必须在共享写入逻辑中强制执行

不只禁用一个下拉框或隐藏一个按钮。

日记录、周矩阵、学生抽屉、常用亮点、自由亮点、观察采用、
批量确认和预览发布，必须读取同一份资格判定结果。
复用已有记录与模型，只补必要的关联、状态和检查，不另造第二份考勤或评价存储。

在实际共享修改入口/命令/reducer/store action和持久化边界检查：
- 当前有权对象和真实记录版本；
- 当前出勤是否提供合法参加范围；
- 要写入的等级、亮点来源是否处于该范围；
- 等级是否属于对象已经采用的评价方案；
- 是否仍处于允许编辑状态。

直接调用已有写入函数、旧组件回调、常用短语采用或伪造“可编辑=true”，
也不能写入缺席范围的有效评价和亮点。

纯前端原型至少做到实际共享业务状态与存储强制检查。
不能以“后端以后再校验”为理由，只做视觉禁用。
反之也不能宣称原型检查已经等于真实产品安全验收。

每次写入在提交时复验出勤/记录版本：
旧页面在出勤修改前排队的评分、亮点保存响应不得覆盖最新缺席状态。
快捷切学生、日期、任务，不能把上一对象的允许状态带到下一对象。

## 4. 出勤改变后，评价和亮点必须联动

### 4.1 出席改为未出席，失去全部参加依据

同一个原子业务变更完成：
1. 保存准确的出勤事实及现有来源。
2. 当前有效课堂等级失效：当前等级引用/值为空，状态为系统“不适用（未出席）”。
3. 相应评价确认覆盖退出有效状态，不保留“已评分A”的有效结果。
4. 该范围中已保存课堂亮点停止作为有效亮点使用，退出计数、预览、建议和新发布。
5. 记录必要的旧值、关联与失效原因，供变更历史查看。
6. 日卡、矩阵、抽屉及任务统计同时更新。

不能出现“请假 + 灰色 A”，也不能只隐藏下拉框，导出仍带 A。
不把“不适用”存成自定义等级、D、零分或“待教师补评分”。

正常修改不要求教师逐条删除受影响的旧亮点。
有实际影响时给予简短说明，例如“未出席，本日评价和相关亮点已失效”；
不为每次出勤调整弹出多轮批准。

保存失败时不得一半变成请假、一半仍保留有效A或亮点。
恢复输入与状态时如实反映失败，不能宣称已保存。

### 4.2 多课次参加范围缩小，但仍有真实参加

只使与失效范围绑定的亮点/依据失效。
日综合评价如果仍有合法参加依据，不因其中一节请假机械删除；
但既有确认覆盖若包含了现在被更正的范围，应标为需要核对其覆盖，
不能仍声称“整个原范围已确认”。

保留教师已填内容供核对，不恢复逐课次等级，
不要求教师重新选择同一个等级才能沿用合法评价。
缺席课次本身不能通过“本日综合”获得评价资格。

### 4.3 未出席改回已出席

不自动复活之前的A、其他等级或失效亮点。
恢复允许操作，评价成为待处理或保留明确的其他合法状态；
由教师重新明确选择、确认或在有权的历史核对中明确恢复。

“正常”出勤的保存不是恢复旧等级的指令。
整个动作的安全撤销可以恢复准确的前一合法状态，
但必须同时校验版本、依赖和后续修改，不得撤回别人/之后的更正。

### 4.4 班主任请假及其他来源更新

不只处理教师手动选择：
已登记请假映射、课次考勤修订等改变真实出勤时，
同样触发资格重算及无效内容的保护。

有可信来源冲突时明确核对，不能为了放行评分默认选“正常”。
保留现有合法考勤更正流程，不反向篡改请假申请，
不新增教师可无理由忽略来源的旁路。

## 5. 亮点规则：不从另一个入口绕过

禁止范围包括：
- 日卡“常用亮点”、自由填写亮点；
- 周矩阵和学生周反馈详情中的亮点；
- 单课次观察“采用为亮点”；
- 已有建议采用、复制和其他会创建有效亮点的动作。

无资格时不能新增、改写成有效亮点、恢复失效亮点或采用模板。
可以查看已有失效记录的必要历史、撤下/删除错误的未发布内容；
不应把“禁止新增”变成连错误内容也无法撤下。

### 5.1 关联范围尽可能自动带入

从日卡/日期单元格进入，自动带入真实学生、任务和日期。
从具体课次观察采用，保留实际课次来源，不能转挂到另一节有出勤的课来绕过规则。

学生整周详情里创建新的“课堂亮点”时：
- 已有明确日期/课次上下文则直接使用；
- 没有上下文且只有一个合法已参加日期，可以明确带入该日期；
- 有多个候选时，用最少的选择明确发生日期；
- 本任务本周期无合法参加范围，则不能新增该周期课堂亮点。

不需要增加必填长篇事例、审批或证据上传。
但不能用一个完全无日期、无可核对来源的“周亮点”绕过缺席限制。

### 5.2 存量与独立内容

现有无日期周亮点不能按当前打开日卡的缺席状态一锅端删除。
先读取其真实来源或原有适用范围；
涉及本次缺席更正而无法确定依据的，保留原文待核对，
不自动认定有效，不猜一个出席日期替它挂上。
可以明确关联合法依据或从本次发布排除，不强制重录所有历史资料。

其他已出席日期、其他合法教学任务中的亮点保持不变。

这里约束“课堂评价/课堂亮点”，不是禁止缺席学生的一切信息：
- 出勤原因、必要内部备注、事实核对、既有学生资料仍可维护。
- 真实作业提交与作业质量独立；缺席学生交了作业，仍可评价该作业。
- 既有有明确非课堂来源的有效内容不自动删除。
- 不额外新建作业亮点模块或通用事件分类平台。

内部备注/课次参考不能被自动当成可发布的课堂亮点。
不通过自然语言关键词去猜出勤或批量审查全部评语；
仅有依据、经教师明确采用且通过资格检查的内容进入结构化评价/亮点。
现有个体评语可空和正常编辑规则保留，系统建议不能继续引用已失效课堂赞扬。

## 6. 批量确认、统计与“不适用”

### 6.1 批量规则

“确认本日常规”“批量确认常规情况”“确认该生常规”及安全撤销，
全部共用新规则：
- 不将已确认请假/缺勤/在他班覆盖为正常。
- 不向未参加范围填默认等级或亮点。
- 不将未来课次、不适用对象或来源冲突算成常规。
- 搜索、分页、只看待处理不静默改变既定批量范围。
- 跳过人数和原因简洁准确，重复执行不造新值。
- 不改其他日期、任务、作业结果或评价标准。
- 自定义八级、文字方案、无默认等级遵守相同参加资格。

保留真正减负的合法操作：
教师明确确认一组“出勤尚未登记、实际均正常”的学生时，
可按既有常规动作一次保存正常出勤及合适默认评价；
在一次变更中先确认出勤，再校验并写评价。
不强制先逐人点击出勤、再来一次全班评分。
该动作不能把已有缺席事实当作普通空白。

### 6.2 状态和计数

“不适用（未出席）”与“未填写/待评价”“明确不评价”不同。

已经明确未出席且该生本日全部适用范围结束：
- 不再计入欠课堂评价；
- 不计入已实际评分人数、等级分布或亮点数量；
- 出勤、例外事实、合法成员和周反馈受众保留；
- 可在既有处理完成口径中作为“该维度已明确不适用”处理，
  不把它冒充为评分已完成。

示例：12名学生，10名真实参加并评价、2名全日未出席：
可以表达评价已处理妥当，但不能声称“12人已评分”。
若需要展示细节，区分10人已评与2人不适用。
全体均无可评价参与时显示“无需评价”，
不显示“全部学生A”、无依据的0%或假100%评分。

仍有未来适用课次、出勤未知或冲突时，
保持相应尚未完成/待核对含义，
不能把未知当缺席排除分母以凑齐完成。

任务总体“已处理记录”继续按既有明确定义计算；
本轮只修不适用与参与判断，不随意重做全部统计公式。
日卡评价状态、考勤待核对、周发布状态保持独立。

## 7. 发布、家长预览和历史保护

1. 当前周准备、家长预览、发布校验及新输出均读取最新有效的资格与结果。
   未出席范围只表达获准出勤信息及必要的“不适用”，不带等级或课堂亮点。
   不向家长附带全部内部原因或已失效文字。

2. 发布前再次校验：
   如果待输出数据仍包含“无参加依据 + 有效课堂等级/亮点”，
   必须作为可定位问题阻止该错误内容发布。
   不能仅在预览上隐藏、最终payload仍然发送，
   也不能跳过校验然后静默删几条内容就报告发布成功。

3. 正确归一化为不适用后，不要求教师给该生补评分；
   该学生合法的出勤情况和其他有效周内容可以按规则发布。
   不从周反馈受众中移除缺席学生，不将家长跳过来消除错误。

4. 日卡只是周预览入口：
   同任务同周期的周一/周三日卡，默认整周范围一致；
   来源日、搜索和待处理筛选不限制周内容。
   保留提前阶段发布、补发布、组合任务及明确受众规则。

5. 已发布版本不原地改写。
   若更正后发现上一发布版存在不适用的等级/亮点：
   当前草稿/下一版不得继续采用；
   使用现有“有未发布更正/修订”机制提示并允许明确更正发布。
   旧报告、旧图片保留为当时快照，不自动重发或偷偷换文件内容。

6. 系统模板、依据摘要和建议不得继续引用失效等级/亮点，
   不根据已失效的A生成“本周积极参与”等事实。
   对已经由教师编写的自由周评语，不自动改写全文；
   涉及受影响依据时提供现有核对通路，不宣布机器已修正所有文字。

7. 打开、关闭和刷新预览不产生数据修改或无意义的版本差异。
   实际出勤更正及依赖内容失效必须形成真实差异；
   不能重设更新时间、转换空值或遍历重新保存全班而制造17条“更正”。

## 8. 修复存量状态，不用重置掩盖

当前原型很可能已保存“请假 + A”等组合，需要定向修正：
- 核对现有模拟记录及各旧入口实际写法，列出本轮影响对象。
- 对能够确定为无参加范围的有效等级/课堂亮点做一次性、
  范围明确、可追溯、可重复运行不重复失效的修复。
- 当前有效等级字段不能继续留着A供其他选择器、预览或输出读取。
- 原文和旧值只保留在现有变更历史/隔离的失效记录中。
- 无法确定出勤或亮点范围的，保留原资料并标待核对，不猜事实。

不要在React render/每次打开弹窗时修改数据或新增历史版本。
可以复用有版本的存储修复入口；
修复完成前，读取投影至少不能把已识别的矛盾当成有效评价，
提交与发布仍必须拦截。
修复失败要准确说明，不能报成功、不能丢输入。

不清空全站localStorage、不重建全校数据、不删除已发布历史，
不改演示日期或只修改图片里的单个学生来制造通过结果。
初始化的新正常示例须符合新规则；
刻意构造的非法样例只用于测试，并保证正常演示不自动再播种回来。

## 9. 顺手完成 r3 的有限呈现纠偏

本轮不大改版式，修正这些已经明确的要求：

- 日弹窗不显示 DEMO_STU_*；有真实学号且确有需要时显示学号，否则省略，
  不填“未设置”或伪号占空间。
- 周预览不显示 TASK_*、HW_* 这类内部键。
  组合任务用真实班名＋规范分工区分，不能删除ID显示后P1/S1变成两个同名项。
- 周期明确表达一次，不重复在标题、副标题、选择器和长说明中堆叠。
- “已从本日切换整周……”的大段常驻说明收敛；
  周反馈标题、范围和返回动作必须仍然明确。
- 修正本轮可见的作业页签乱码，复用现有文字资源。
  不借此启动作业第二阶段全面改造。
- 图4需要可理解的整周后续安排信息：
  已发布/可发布日期与未来日期区分，未来课不生成可发布事实；
  不能写“整周”却实际只用来源日过滤数据。
- 当前图1的课堂100%只表示既定已发生范围的处理情况，
  不表示未来课堂完成、作业全部完成或已经发布。
  状态计算与文案必须和实际定义一致。

布局、尺寸和颜色不作本提示词规定，由 v0 自行设计。
必要错误、批量范围和无评价资格的简短原因不能被隐藏。
不增加满屏规则说明或为每位缺席学生重复弹窗。

## 10. 必须实际验证的场景

逐项记录 PASS / FAIL / NOT_RUN，提供实际操作及保存后重开证据。
逻辑测试补充真实浏览器操作，不用编译或静态截图替代。

| 编号 | 场景与预期 |
|---|---|
| T01 | 单课次日：分别选择请假、缺勤、在他班。等级立即不可写，显示不适用；常用、自由、采用观察的课堂亮点均不可写。 |
| T02 | 先保存正常+A和课堂亮点，再改为全日未出席。有效等级为空、相应亮点失效，各视图/计数/预览一致；必要历史仍在。 |
| T03 | 将T02改回正常。不得自动恢复A或亮点；明确再次评价后才有有效结果。 |
| T04 | 非出席→正常→非出席快速切换并延迟评分/亮点保存响应。最终不能被旧响应写回等级或有效亮点，失败与重试准确。 |
| T05 | 同日两节均未出席，包括请假+在他班混合。不能用“混合出勤”绕过禁止，日评价不适用。 |
| T06 | 同日一节正常、一节请假。仅基于实际参加部分可以日评价；缺席节次的亮点被拒绝，已参加课次的有效内容不误删。 |
| T07 | 上午全部未出席、下午未来。当前禁止评分，不提前宣告整日完成。下午明确参加后允许记录，但不自动复活旧值。 |
| T08 | 迟到/早退但实际参加可以评价；原因待核实不等于出勤待核实，不强制填原因。实际零参加不能仅换“迟到”标签绕过事实。 |
| T09 | 出勤未知、来源冲突、未来/取消或不适用课次，不假定到课；有一节明确参加、另一节未知时不误宣告整日覆盖完成。 |
| T10 | 班主任请假来源更新后，各入口重新判断；不只处理手动下拉，不改原请假申请。 |
| T11 | 批量和逐生常规确认跳过已知未出席/例外，保护已有手动值；真实正常空白候选可一次确认出勤+默认评价，不增加逐人步骤。 |
| T12 | 四级、八级、文字方案和无默认等级都不能绕过资格；不适用不存为D、0分或某自定义等级。 |
| T13 | 日卡、周矩阵、学生抽屉、单课参考采用、直接共享写函数都拒绝同样的非法输入；不是只修当前弹窗。 |
| T14 | 学生周亮点：不能无日期绕过缺席限制；有合法其他日期内容仍可查看/维护。缺席日不删除整周其他合法亮点。 |
| T15 | 12人中10人参加并评价、2人未出席：待评价为0但实际评分人数为10；全员未出席显示无需评价，合法名单/考勤/受众不减少。 |
| T16 | 缺席学生已提交作业仍可按该作业方案评价；不自动免做、不抹去作业质量、不把未登记改成未交。 |
| T17 | 有未出席但残留有效等级/亮点的拟发布数据，发布校验拒绝；处理为不适用后可以发布合法出勤和周内容。 |
| T18 | 已发布错误组合：旧快照不变，当前更正有明确差异；新版本不带失效内容，不自动重发。 |
| T19 | 同任务不同日期日卡进入周预览得到同一默认周范围；未来课有准确上下文但不被评分，不受学生筛选限制。 |
| T20 | 单纯打开预览、关闭、刷新不产生公共总结或全班记录“修改”；真实更正正常形成差异。 |
| T21 | 定向存量修复运行两次、刷新重开：不重复失效、不复活错误值、不清空其他资料；缺少依据的内容准确待核对。 |
| T22 | 安全撤销不能覆盖之后修改；失权、跨任务、跨学生和旧版本写入不成功，当前上下文与输入保留正确。 |
| T23 | 无内部ID和乱码，任务可区分、说明不冗长；同页三视图/日弹窗、常用原因亮点、学生资料和轻量布置作业均可达。 |
| T24 | 回归完整课表来源一致、真实拖拽和既有修改保护；不因课堂禁评锁死排课或新建其他业务模块。 |

必交一条连续操作证据：

“日卡正常出勤、评价A、有一条亮点 → 改请假 → 等级/亮点失效
→ 打开周矩阵及学生抽屉核对 → 预览周反馈核对 → 刷新重开
→ 改回正常 → 确认旧值没有自动恢复”。

再交：
- 单课次与多课次混合出勤对照。
- 批量常规确认包含缺席学生的负例。
- 未出席但有真实作业结果的独立性对照。
- 旧版本快照与新更正预览的对照。

无浏览器能力或某项无法运行时如实写 NOT_RUN，
不用直接改store再截结果冒充操作完成。
