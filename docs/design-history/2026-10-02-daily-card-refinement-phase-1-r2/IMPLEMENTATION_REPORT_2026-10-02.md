## 一、本轮替代 r1 的点击与状态要求

| r1 行为 | r2 行为 |
| --- | --- |
| 日卡状态主要按时间推断（已结束即视为可完成） | 状态从每位学生日评价的真实覆盖计算：待评价／部分待补／考勤待核对／已完成／未开始／无适用对象／读取失败，时间状态单独展示 |
| 同任务多课次合并卡无明确标识 | 显示“合并N节”标识与逐节时间／教室，不称“连堂”；统计仍按实际课次数 |
| 课次安排单课卡点击直接进入整周反馈 | 原位打开课次详情（URL `?lesson=`），关闭恢复 `?focus=` 与周次／筛选／视图；“本日正式评价”“打开整周反馈”为显式入口 |
| 无课次观察 | 新增可选“本课教学观察”与“指定学生观察”，仅作参考 |

r1 的其他要求（日评价、日级出勤、日卡布置作业、旧单课次录入只读）继续有效，此前验收不倒写。

## 二、实现说明

### 1. 评价状态、合并属性与时间状态
- `lib/mt/daycards.ts`：日卡状态由 `evaluation`（基于该日每位适用学生的日评价覆盖与考勤核对，明确不评价／不适用不计欠填，未知仍需处理）、`merge`（同任务同日多课次，`mergedCount`）、`time`（未开始／进行中／已结束）三个独立字段组成，互不推导。
- `components/mt/day-cards-view.tsx`：分别渲染状态标签与“合并N节”标识。工作台／我的教学沿用同一 `daycards` 计算，未形成第三套算法。

### 2. 复用的真实实现
- 课次详情：新组件 `components/mt/lesson-detail.tsx`，被三个入口复用：本周教学安排单课卡（`week-schedule.tsx`）、按日记录的课次标签（`day-record.tsx`）、我的完整课表浏览态（`app/(app)/timetable/my/page.tsx`，活动或他人课次仍回落到原 `CardDetail`）。
- 正式日评价：仍为 r1 的日评价写入（每生每日一条），详情只提供“进入本日正式评价”跳转。
- 观察：`lib/mt/store.tsx` 新增 `observations` 集合与独立写入器，仅写该集合；作者校验（不能改他人观察）、清空即删除、去抖自动保存＋失焦立即保存。
- 考勤更正：详情中“指定学生 → 本节考勤更正”写入同一份课次考勤明细（与日卡、周矩阵、学生抽屉同源）。
- 学生反馈详情（`student-drawer.tsx`）：在对应课次下以“课次观察（参考，不计入评价）”区块显示全班观察与该生观察，不进入评价字段、矩阵、评语或周总结。

### 3. 保留的原有能力
完整课表的手动调整、空格新增、课节编辑、拖拽及草稿／确认应用流程未改动；日卡“布置作业”仍走统一作业流程；发布历史与快照未改动。观察写入器不触碰排课草稿、安排版本、评价或发布数据。

## 三、实际问题与原因

1. **完整课表中自己写的观察被锁为“由其他老师记录”**
   原因：完整课表页向 `LessonDetail` 传入的是课表模块教师 ID（`lin`），而观察作者使用我的教学模块的教师身份（`useTeacherId()`），两套 ID 不一致导致作者校验失败。
   修正：完整课表页改传 `useTeacherId()`。已在浏览器复测：同一观察在完整课表中可编辑（`disabled=false`）。
2. `?view=day` 参数无法切换视图：实际参数为 `view=days`，属测试时误用，非缺陷。
