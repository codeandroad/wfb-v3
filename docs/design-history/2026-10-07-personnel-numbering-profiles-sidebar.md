## 二、员工编号与学生编号：共用业务规则

### 2.1 三种标识不能混用

| 标识 | 用途 | 稳定性 |
| --- | --- | --- |
| 内部人员 ID | 关联人员主档、账号、职责及业务记录 | 必须存在且稳定；改号、清号不改 ID |
| 员工编号／工号、学生编号／学号 | 学校正式业务编号 | 可以为空；受权设置、修改、清空；历史占用保留 |
| 学生列表“序号” | 当前可见列表的行序 | 当前实现按筛选后结果从 1 编排；不存入人员主档，不用于业务关联 |

待编号是**已成功建档**，不是草稿、失效、未开户或无权限。是否有编号，不决定是否具有账号、角色或教学资格。

### 2.2 学校级双预设

只允许两种受控预设，不开放任意正则、脚本、自由位数或按人临时换格式。

| 项目 | 标准版 | 简短版 |
| --- | --- | --- |
| 结构 | `Code(2) + YYYYMM(6) + Type(1) + NNN(3)` | `Code(2) + YYMM(4) + Type(1) + NNN(3)` |
| 长度 | 12 位 | 10 位 |
| 学生示例 | `AB199809S028` | `TG2109S028` |
| 员工示例 | `AB202108E012` | `TG2108E012` |
| 年份边界 | 合法四位年份，不能是 `0000` | 固定 2000—2099，不猜世纪 |
| 默认 | 新学校默认 | 学校明确选择 |

共用规则：

- `Code` 为两位 ASCII 大写英文字母；学生 `S`、员工 `E` 位于流水号之前，不能放末尾。
- 月份 `01—12`；流水 `001—999`，不能使用 `000`；非空号码只接受 ASCII 大写字母和数字，不自动修正小写、空格、全角字符或连接符。
- 同校使用同一个当前预设，按人员类型及完整首次年月分别计数。学校身份和权限不依赖两位编号代码。
- 天行编号代码为 `TG`，采用简短 10 位；品牌简称仍为 `TGS`，学校中英文名与 Logo 不变，禁止全局替换 `TGS → TG`。
- 发号年月来自**本校首次入学／入职**，不是建档、当前、邀请、导入或发号的日期。
- 内部号段使用学校稳定 ID、类型和完整 `YYYYMM`。简短版只缩短显示，不缩短真实日期。
- 简短版 `00` 表示 2000，`99` 表示 2099；1998、2100 等真实资料可以记录，但不能按短版发号、猜世纪或为个别人悄悄切换标准版。
- 学校配置沿用既有授权入口；正式发号后不作为普通个人偏好任意修改。

### 2.3 新增时的意图与界面

**业务结果有三种，员工新增界面只有两种选择。**

| 界面／输入 | 保存结果 |
| --- | --- |
| 默认“手工填写”，编号留空 | 成功建档，显示“待编号”，不占号 |
| 手工填入合法未占用号码 | 保存该正式编号 |
| 明确选择“自动生成” | 按本校首次入职／入学年月及当前预设发号；成功保存时才正式占号 |

- 员工新增表单不再提供独立“无需编号／暂不编号”按钮。留空即表达暂不编号；这不取消业务上的待编号状态。
- 自动编号缺少必要日期时提示补填；不使用首次参加工作、毕业、过往任职或当前日期代替。
- 切回手填并留空后不能继续发号；日期后补、邀请、激活、角色变化或重新登录均不得自动补号。
- 手填时已有首次日期则检查年月一致；首次日期为空时，合法未占用号可接受，但不从号码反填日期。学生原有学籍必填条件仍独立有效。
- 配置错误、年份越界、号码占用或号段耗尽必须具体提示，不能静默换格式或降为待编号。
- 预览、未保存输入、取消均不占号；重复提交不能重复建人或重复发号。

### 2.4 修改、清空与历史保护

- 有权管理员可在原主档上设置、修改或清空编号；不新建第二个人、不重新邀请、不更换内部 ID。
- 员工默认详情／首页只读显示号码或“待编号”。实际路径为：**教职工详情 → 编辑资料 → 编号行“修改／设置” → 编号维护 → 返回资料编辑**。
- 编辑页的常驻编号区域只包含“员工编号”、当前值和轻量文字操作，不使用大边框说明卡、分段图、长篇机制提示或常驻维护表单。
- 有号按钮为“修改”，空号按钮为“设置”；不再使用“修改或清空”。进入维护后仍保留手填、自动生成及有号时的清空功能，精简外层文案不等于删除清空业务。
- 维护时明确目标人员、旧号和新结果，执行格式／日期／占用检查及一次明确确认；备注选填。
- 失败或取消保留旧号；新旧号相同不记虚假变更。记录操作类型、人员、旧值、新值、操作者、时间及实际备注。
- 清空后显示待编号，历史号码仍归原人员，不释放占用；人员、账号和业务关系不删除。已下载文件不会自动更新。
- 普通教师不能从本人教师主页或账号中心自行改工号；隐藏按钮不是权限校验，实际操作仍须受权。
- 普通资料保存不自动改号。首次日期修改导致可可靠解析的年月不一致时，只给简短非阻断提示；清空日期不自动清号，同月内日期更正不产生编号���常。
- 旧 `TGS` 长号和末位类型字符可作为历史记录保留，不批量截断、移位或强迫一打开详情就迁移。
- 自动发号取可用流水，避开当前及历史占用和同批拟提交手工号；只有 `001—999` 全部不可用才算耗尽。改号、清号、离职、离校及格式变化均不重置历史逻辑归属。

## 三、教师／教职工资料现行设计

### 3.1 常用资料

- 姓名沿用原必填要求；英文名／常用名移入直接可填写的常用区域，复用原字段和历史值，不在更多资料重复。
- 英文名选填，不替代正式姓名、登录名、工号或独立设���的主页显示名，不额外增加英文能力或唯一性限制。
- 保留联系电话、邮箱、所属部门、当前职务和本校首次入职资料；所属部门与职务控件对齐。
- 当前职务使用既有名单，可搜索、选择、清空；删除“其他，填写本次职务”分支，不换名称恢复它。历史自定义职务仍正常回显，普通保存不能清空或强制重选。
- 部门与职务是人事资料，不是系统角色；资料编辑不自动授予角色或安排职责。
- **所有选填项不再加“（可选）”后缀**。删提示不代表改成必填；保留必要校验和简短帮助，不重复解释全部业务机制。

### 3.2 日期：最后修订为“首次入职日期”

| 时间 | 业务含义 | 是否用于本校工号 |
| --- | --- | --- |
| 首次入职日期 | 第一次正式加入当前学校 | 是，只读取其年月 |
| 首次参加工作年月 | 个人第一次参加工作的时间，可能在其他单位 | 否 |
| 教育经历毕业时间 | 该段教育的毕业时间 | 否 |
| 过往工作经历起止时间 | 某段过去工作的时间 | 否 |
| 本校任职历史生效时间 | 任职、离职、返聘等实际业务事件日期 | 不自动替代首次入职日期 |

- 员工新增、普通编辑、详情及员工编号自动生成操作采用“首次入职日期”文案；当前表单使用日期控件，新填写精度为 `YYYY-MM-DD`。
- 日期仍选填，不默认填今天，不另设“本次任职开始日”、核实人、核实状态、原因、附件或“保存首次年月”的独立步骤。
- 历史 `YYYY-MM` 原值保持兼容；只知道年月不能补造成当月 1 日。当前编辑控件提示历史年月，不修改则保留原记录。
- 例如首次参加工作为 1998 年、本校首次入职为 2021 年 8 月，应按 `202108` 的本校年月发号，不能因首次工作早于 2000 年阻止合法短版工号。
- 这次日期控件修订针对员工资料；不借此删除学生已有真实学籍日期要求，也不宣称所有导入模板标题已经统一更名。导入字段须保持与旧文件的兼容和正确业务映射。

### 3.3 更多资料与教育经历

- 更多资料默认可收起、可全部留空，不要求展开，不计算资料完整度，不影响建档、编号、账号和教学使用。
- 后续修订：**性别移到常用资料区姓名输入框右侧**，更多资料不再重复采集；原性别位置改为可选的**出生年月**。新增与编辑复用同一表单，窄屏沿用响应式堆叠。
- 出生年月使用 `birthMonth`、月份控件及 `YYYY-MM` 精度；不补造具体生日，不用于自动编号、工龄、角色资格或权限推断。
- 原独立学历位置仍为**出生地**；保留微信号、兴趣爱好、首次参加工作时间等背景字段。
- `3c5cf49` 已接入出生年月的新增保存、编辑回填／更新字段白名单和受限资料详情展示；沿用现有原型保存流程，不代表新增生产数据库或字段级后台授权。出生年月不自动公开到教师主页、普通名单或搜索摘要。
- **学历进入每条“教育经历”内部**，与毕业学校／就读院校、专业、毕业时间一起维护；不再保留另一份常驻最高学历填写框。
- 学历可空，可选既有学历范围；它不是学位、职称、教师资格或系统角色。
- 教育经历可添加一条或多条，支持增改删，随普通资料保存。只填学历、学校等部分信息也可保存；全部为空的临时行不形成虚假经历。
- 学校及专业可正常输入文本，不强制使用本系统学校／学科字典。毕业时间可为空、年份或年月，不补造具体日，不自动认定已毕业。
- 不要求证书、GPA、证明人、核实、审批、学历排名或资格推断。
- 旧独立学历值通过兼容逻辑进入教育经历，避免字段迁移丢失。当前 `educationExperiencesOf` 保留已有经历，并在需要时补入仅承载旧学历的兼容记录；保存后不再维护平行概况学历。
- “特长／擅长领域”从普通表单采集和详情展示中移除，不换名字保留，也不将旧值挪进兴趣、学历或教学介绍。移除控件不等于删除历史存储；教师主页已有教学介绍不属于删除范围。

### 3.4 过往工作经历

- 可记录多条工作单位、当时岗位／职务、起始时间、结束时间；可增改删，随同普通资料保存。
- 时间可为空、年份或年月，保留真实精度；完全空白的临时行不保存，部分信息可以保存。
- 能明确比较且结束早于开始时局部提示；不同经历允许合理重叠，未填结束时间不自动表示仍在职。
- 外部单位和过去岗位不进入本校组织／职务字典，不恢复“当前职务其他填写”的分支。
- 不从最早经历或毕业时间推算首次参加工作时间，不计算工龄待遇；背景经历不自动生成本校正式任职记录、授角色、安排工作或改变在职状态。

### 3.5 阅读、权限与离职入口

- 新增、邀请内新增、编辑、详情共用同一人员资料；字段移动和某条经历增删不能覆盖其他字段或其他经历。取消不提交，保存后重新进入可读取。
- 首页／默认资料展示简洁干净，不常驻编号维护控件、长篇机制说明或全部背景履历。
- 出生地、教育、工作背景及更多资料沿用人员资料权限，不自动公开到教师主页、留言名片、普通名单、人员选择器或搜索摘要。
- **办理离职移入“任职历史／任职管理”的低频通路**，不与编辑资料、查看账号、教师主页、安排职责并列为默认主要操作；新增成功或普通编辑处不能复制醒目快捷入口。
- 有权管理者仍能清楚找到入口并取消返回；查看历史或打开入口不执行离职，实际办理必须保留目标、生效时间、权限、影响说明和明确确认。
- 普通资料保存、经历删除、日期修改或编号清空均不办理离职；已离职者不能重复离职。历史人员、编号占用与业务记录保留，不新增多级审批或完整 HR 系统。

## 四、学生列表：姓名前独立序号列

- 删除学生姓名左侧的圆形文字／首字占位元素。这种表现不适合以中文姓名为主的名单。
- 当前不显示虚构照片或新的头像占位；未来有真实学生照片时可再设计头像，本次不实现照片上传或存储。
- 表格姓名列左侧新增独立“序号”列；姓名本身仍可点击打开详情，不能用序号替代姓名操作入口。
- 当前实现按筛选后可见行的 `index + 1` 显示序号；它不是正式学生编号，不持久化、不占号、不用于搜索匹配或人员关联。
- 正式学号仍用于已有资料和姓名／学号搜索；当前列表不将学号当作序号或默认名单列。
- 保留行政班、配置显示字段、状态、详情操作、筛选搜索、显示设置、新增与集中导入入口及无匹配空状态。

## 五、左侧栏折叠／隐藏按钮：最终位置规则

目标是与 Owner 描述的 v0 交互一致，不把折叠按钮始终固定在主内容区。

| 状态 | 侧栏与主区 | 按钮位置 | 动作 |
| --- | --- | --- | --- |
| 左侧栏展开 | 左侧栏正常显示，主区使用剩余宽度 | **左侧栏右上角**，品牌区域右侧 | 点击“折叠左侧栏” |
| 左侧栏隐藏 | 左侧栏不占布局宽度，主区使用整屏可用宽度 | **主内容区左上角**，顶部栏左侧 | 点击“展开左侧栏” |
| 再次展开 | 恢复原导航与主区布局 | 展开按钮消失，折叠按钮回到左侧栏右上角 | 可继续折叠 |

补充规则与现状：

- 展开状态不在主区重复显示切换按钮；隐藏后不能把恢复按钮留在已经隐藏的侧栏内。
- 折叠不导航、不清空内容，不改变当前路由、选中导航或用户工作上下文。
- 两个状态的按钮都有明确可访问名称、`title`、`aria-expanded` 和指向侧栏的 `aria-controls`；图标为关闭／打开左面板。
- 当前 `AppShell` 通过父层 `sidebarOpen` 状态控制侧栏与顶栏；默认展开。本轮未要求跨刷新记忆，不将它描述为已持久化偏好。
- 当前侧栏与恢复按钮沿用 `md` 及以上的桌面布局，小屏既有底部导航继续保留。本次没有新建手机侧栏抽屉。

## 六、导入、邀请及原型边界

### 6.1 继续有效的设计约束

- 保留真实本地 Excel／CSV 解析、表头映射、预览和文件内校验，复用集中导入中心，不在人员页另建上传模块。
- 新增型��入编号列可选，空号默认待编号；多个空号不算重复。自动生成必须明确指定行，不覆盖已有手工号或未选中的空号行。
- 同批可有手工号、自动号和待编号，错误具体到行；预览不占号，提交重新校验并避开同批手工号，不无提示部分成功。
- 现有可选字段缺列不阻止导入；首次参加工作与本校首次入职不能映射到同一字段。多条经历不创建多名员工，不发明大量经历必填列或独立简历导入中心。
- 已有更新型导入如存在：编号列缺失或空值表示不修改，不隐式清空／改号；不为这轮新建整套更新导入系统。
- 邀请内新增成功后返回同一邀请上下文并选中同一人员；取消后续邀请不删除已建主档。邀请、重发、激活不自动补号。
- 搜索与回导沿用稳定人员关联及学校来源，不能仅凭姓名、空号、行号或两位代码匹配；历史编号按权限仍应指向原人员。

### 6.2 不把原型当正式后台

此前完整规范明确允许共享本地原型状态模拟人员保存、查重、权限及历史；当前编号账本也使用内存及浏览器会话状态。这不构成生产数据库、并发发号锁或真实授权服务。

真实本地文件解析与模拟后台操作必须分开描述；邀请发送、正式账号停用、生产数据迁移和生产并发安全不属于这些界面修订的已交付内容。本次仅归档，不补做后台，也不把全部学生编号维护或全部导入通路的设计要求自动记作已实现、已验收。

## 八、明确淘汰的中间表现

不得因参考旧截图、旧提示词或历史验收条目而恢复以下设计：

1. 编号留空即自动生成、所有人建档必须有号、工号永远不可修改。
2. 员工新增独立“无需编号／暂不编号”按钮；当前应为手填留空表达待编号。
3. 默认资料页上的“修改或清空”按钮和编号维护大卡片；当前应进入编辑页，用轻量“修改／设置”入口。
4. 员工当前表单“首次入职年月”标题，以及为普通资料新增核实人、核实原因、独立年月保存步骤。
5. 所有选填字段重复“（可选）”后缀；性别后独立学历字段；更多资料重复英文名。
6. 资料页、新增成功或普通编辑中常驻主要“办理离职”按钮。
7. 学生中文姓名左侧的圆形文字占位、把列表行序号当正式学号。
8. 左侧栏展开时仍把折叠按钮放在主区，或侧栏隐藏后无法从主区左上角恢复。

只替代与本次确认冲突的表现；既有隐私、权限、历史保护、职责与账号边界及无关教学模块继续保留。
